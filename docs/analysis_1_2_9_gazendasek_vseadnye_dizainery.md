## Общая характеристика книги

Книга Гэзэуэя — **единственное в своём роде пошаговое руководство** по системному геймдизайну, сфокусированное на практическом создании игровых систем с использованием электронных таблиц. В отличие от большинства книг по геймдизайну, которые дают высокоуровневые концепции, эта книга углубляется в **механику проектирования**: от формализации атрибутов до балансировки диапазонов и вероятностных моделей. Основной инструмент — электронная таблица, что делает методологию **непосредственно программируемой** для AI-системы.

Книга состоит из 20 глав, которые можно разделить на 5 логических блоков:
1. **Фундамент** (главы 1–3): определения, роли, методология вопросов
2. **Инструментарий** (главы 4–6): инструменты, электронные таблицы, функции
3. **Проектирование систем** (главы 7–12): абстракция, идеи, атрибуты, организация, числа, основы
4. **Балансировка и анализ** (главы 13–17): диапазоны, экспоненциальный рост, данные, макросистемы, тонкая настройка
5. **Коммуникация и вероятность** (главы 18–20): психология, теория вероятности, дальнейшие шаги

## Глава 1. Игры и игроки: определения

### Определение игры — 5 критериев (чек-лист)

| # | Критерий | Пояснение | Пример |
|---|----------|-----------|--------|
| 1 | Искусственные, заранее определённые правила | Правила созданы людьми, не продиктованы физикой/биологией | Спортивная борьба vs. уличная драка |
| 2 | Игрок может влиять на исход | Без влияния игрока — не игра | Шахматы (влияет) vs. Candy Land (не влияет) |
| 3 | От игры можно отказаться | Законы обязательны, игры — нет | Баскетбол (можно не играть) vs. ПДД (нельзя отказаться) |
| 4 | Игровые сессии ограничены по времени | Есть начало и конец сессии | Клуб бойскаутов — не игра (постоянное членство) |
| 5 | Внутренние награды | Ценность только внутри игры | Шашки (захваченная шашка) vs. Работа (зарплата) |

**Различие головоломки и игры**: в головоломке нельзя проиграть — можно только прекратить попытки. В игре возможно поражение.

**Различие игрушки и игры**: у игрушки нет правил; многие компьютерные «игры» с модификациями — скорее игрушки.

### Характеристики игрока (профиль аудитории)

| Атрибут | Категории | Применение для AI |
|---------|-----------|-------------------|
| Возраст | Дети/подростки vs. взрослые | Ограничения сложности, когнитивные требования |
| Пол | Малоинформативный атрибут для геймдизайна | Не использовать как основной критерий |
| Готовность к изучению правил | 5 уровней: отказывающиеся → неохотно → нейтральные → принимающие → энтузиасты | **Ключевой параметр для AI**: определяет глубину генерируемых механик |
| Интерес к испытаниям | Отношение неудач/успехов: от 1/100 (казуал) до 15/1 (хардкор) | **Количественный параметр**: AI может настраивать кривую сложности |
| Затраты времени | Время сессии + общее время прохождения | Два независимых параметра для генератора |
| Предпочитаемый темп | Медленный → средний → быстрый; с учётом ритма (стелс: медленно→быстро→затухание) | AI может генерировать паттерны темпа |
| Уровень состязательности | Несостязательная → состязательная → очень состязательная | Определяет необходимость таблиц лидеров, рейтингов |
| Платформа | ПК, консоль, мобильные, настольные, VR | Технические ограничения |
| Уровень навыков | Зрительно-моторная координация, распознавание образов, пространственное мышление, расчёт вероятности | **Параметры для AI-модели игрока** |
| Жанр/стиль/сеттинг/нарратив | Индивидуальные предпочтения | Входные данные для генератора концепции |

### Модели монетизации

| Модель | Плюсы | Минусы |
|--------|-------|--------|
| Одноразовая покупка | Высокий чек, завершённость проекта | Нет повторного дохода |
| Покупка расширений | Возврат игроков, исправление баланса | Меньшая аудитория, diverted ресурсы |
| Микротранзакции | Постоянный доход, низкий порог входа | Восприятие как P2W, «дойная корова» |
| Подписка | Стабильный доход | Высокие ожидания контента |
| F2P + реклама | Низкий порог входа, пассивный доход | Раздражение игроков, низкий ARPU |

### Профиль аудитории — шаблон для AI

Книга даёт формализованный **шаблон профиля аудитории**:
- Название игры
- Возрастная группа
- Готовность к изучению правил (1–5)
- Отношение неудач/успехов
- Время сессии / общее время
- Темп игры (описание)
- Уровень состязательности
- Платформа
- Требуемые навыки
- Жанр / стиль / сеттинг
- Тип монетизации

**Для Gidede**: этот шаблон → входная форма для генератора концепции.

## Глава 2. Роли в игровой индустрии

### Иерархия ролей

| Уровень | Роли | Связь с системным дизайном |
|---------|------|---------------------------|
| Управление | Продюсер, директор, ведущий дизайнер | Определяют приоритеты, утверждают концепцию |
| Специалисты | Системный дизайнер, дизайнер уровней, дизайнер контента | Системный дизайнер — основная аудитория книги |
| Производство | Программисты, художники, аниматоры | Реализация систем |
| Гейм-дизайн | Системный, уровневый, нарративный, UX | Системный = данные + баланс |
| QA | Тестировщики, аналитики | Валидация баланса |
| Нарратив | Нарративный дизайнер, сценарист | Интеграция сюжета с системами |

**Ключевое различие**: системный дизайнер работает с **данными** (атрибуты, формулы, баланс), а не с кодом или визуалом.

## Глава 3. Как задавать вопросы

### Научный метод в геймдизайне (8 этапов)

1. Формулировка вопросов для игрового тестирования
2. Сбор информации и ресурсов
3. Формулировка объясняющей гипотезы
4. Проверка гипотезы экспериментом (воспроизводимым способом)
5. Анализ полученных данных
6. Интерпретация данных и формулировка выводов
7. Публикация результатов
8. Повторное тестирование

### Перевод качественных вопросов в количественные

| Плохой вопрос | Хороший вопрос |
|---------------|----------------|
| «Достаточно ли увлекателен третий уровень?» | «Могут ли 80% игроков пройти третий уровень менее чем за 2 минуты, перезапустив его минимум 2, но не более 5 раз?» |
| «Достаточно ли труден босс?» | «Закончился ли первый бой с боссом неудачей для ≥85% игроков? При победе — использовали ≥70% оружия и бой длился ≥5 минут?» |

**Для Gidede**: AI-ассистент должен **автоматически переформулировать** качественные вопросы в количественные, используя measurable критерии.

### Предвзятость согласия (acquiescence bias)
Добровольные тестировщики заранее настроены отвечать положительно → простые опросы искажают результаты.

### Техника обращения за помощью (8 шагов)
Структурированный алгоритм: подумать 10 минут → перечислить действия → описать попытки → добавить благодарность → перечитать с позиции незнающего → настроиться на правильность ответа → точно следовать → если не сработало — повторить.

## Глава 5. Основы электронных таблиц

### Иерархия контейнеров данных
**Ячейка → Столбец/Строка → Лист → Рабочая книга**

### Ключевые символы и операции

| Символ | Значение | Пример |
|--------|----------|--------|
| `=` | Активация формулы | `=A1+B1` |
| `()` | Порядок операций / контейнер функции | `=SUM(A1:A5)` |
| `""` | Текст | `="Hero_"&A1` |
| `+` `-` `*` `/` `^` | Арифметика и степень | `=A1^2` |
| `&` | Конкатенация текста | `="Cha_"&B2` |
| `!` | Ссылка на другой лист | `=Monsters!B2` |
| `:` | Диапазон | `=SUM(A1:A10)` |
| `$` | Абсолютная ссылка | `=$A$1` |

### Типы листов в рабочей книге геймдизайнера

| Тип | Назначение |
|-----|-----------|
| Справочный лист | Банк переменных: веса, min/max, коэффициенты |
| Вводный лист | Инструкции, цветовое кодирование, контакты |
| Рабочие листы с данными | Данные по типам объектов (оружие, броня и т.д.) |
| Листы вывода/визуализации | Диаграммы и аналитика |
| Лист-свалка | Временные вычисления |

### Цветовое кодирование (система)

| Цвет | Назначение |
|------|-----------|
| Белый на чёрном | Заголовки |
| Рыжевато-коричневый | Ячейки ввода данных |
| Зелёный | Формулы и функции |
| Синий | Подзаголовки / ярлыки |
| Чёрный на белом | Статический текст |

**Для Gidede**: эта структура → шаблон для генерации spreadsheet-подобных моделей в веб-приложении.

## Глава 7. Как на основе реальной жизни создать систему

### Ключевая модель: абстракция реальности

**Аналогия «фотография vs. картина»**:
- Фотография городской улицы → десятки сложных систем (архитектура, водопровод, электричество, движение, погода, общество, закон...)
- Абстрактная картина той же улицы → несколько мазков: люди, деревья, столбы, дороги, небо, здания. Разум «дорисовывает» детали.
- **Разница между фотографией и картиной = разница между реальной жизнью и игрой.**

### Процесс создания системы из реальности

1. **Взять аспект реальной жизни** (укладка вещей в багажник)
2. **Выделить ключевую механику** (заполнение пространства с минимумом пустот)
3. **Абстрагировать** (убрать хрупкость, вес, безопасность)
4. **Добавить для удовольствия** (удаление заполненного ряда = Тетрис)

### Расширенный пример: Палеолитическая охота → Бейсбол

Четыре базовых механики охоты:
1. Метание предметов (глубоко укоренившийся инстинкт)
2. Палки/орудия (увеличение дистанции и мощности)
3. Бег (эволюционная приспособленность)
4. Командная работа (специализация ролей)

Комбинация абстракций → бейсбол (метание + удар палкой + бег между базами + командная работа).

### Сюжет в играх
**Ключевое утверждение**: *«Важна не та история, которую мы закладываем в игру; важна та история, которую игроки получают от игры.»* Задача гейм-дизайнера — предоставить возможности для создания игроками собственных историй.

**Для Gidede**: AI-система должна **извлекать механики из референсов реального мира** и формализовать их в атрибуты и правила.

## Глава 8. Разработка новых идей

### Фундаментальная предпосылка
**Креативность — это навык, а не только врождённый талант.** Развивается упорным трудом.

### «Шведский стол идей» (Buffet of Ideas)
- Список идей с краткими описаниями — **больше, чем можно использовать**
- Строгого формата нет; идеи — краткие описания
- Многие идеи не сочетаются — это нормально

### Сессия мозгового штурма

**Правила**:
- 1 модератор, группа 2–5 человек
- Устранить отвлекающие факторы
- Никакой критики во время сессии
- Фиксировать все идеи (ничего не стирать)
- Длительность: ~1 час

### 9 методов повышения креативности

| # | Метод | Суть | Пример |
|---|-------|------|--------|
| 1 | Плохой штурм | Целенаправленно выдвигать плохие идеи | Снимает страх «неправильного» |
| 2 | Шутки | Начинать с «У меня сумасшедшая идея!» | Лучшие решения из шуток |
| 3 | Строительные блоки | Заменить один компонент на другой | Повозка → сани → мобильный суп |
| 4 | Будущее в прошлом | Предложить неправильное решение, затем спросить «Как оно сработало?» | Не «возможно ли?», а «как станет возможным?» |
| 5 | Итеративные шаги | «Что очень близко к этому?» — цепочка ассоциаций | Лошади → л.с. → мускульный авто → мидии → паста |
| 6 | На полпути | Найти точку между двумя разными идеями | Шутер + фермерство; крафт + урон |
| 7 | Противоположности | Цепочка противоположностей (исключая первый пункт) | Пистоль → цветок → овца → гвозди → молоток |
| 8 | Случайные связи | Случайное слово + тема → сходства/различия | Генератор случайных слов |
| 9 | Поток сознания | 2 минуты непрерывного письма без пауз | К концу появляются «самородки» |

**Для Gidede**: эти 9 методов → **алгоритмы генерации идей** в AI-ассистенте. Методы 3, 4, 5, 6, 7 особенно подходят для программной реализации.

## Глава 9. Атрибуты: как выразить жизнь на языке цифр

### Ключевая аналогия: грамматика игры

| Элемент грамматики | Игровой аналог |
|--------------------|---------------|
| Существительные | Атрибуты (данные) |
| Глаголы | Механики (правила/код) |
| Предложения | Микросистемы |
| Главы | Макросистемы |
| Книги | Игры |

### Определения
- **Игровой объект** — любой отдельный объект, который что-то делает
- **Механики** — правила, регулирующие использование объектов (= код)
- **Атрибуты** — значения, влияющие на правила (= данные)

### Процесс создания атрибутов (4 этапа)

1. **Начальный мозговой штурм** — быстро записать очевидные атрибуты
2. **Мозговой штурм «с фантазией»** — добавить абсурдные предложения; количество > качества
3. **Исследование** — сначала реальные атрибуты (статистика, медицина, спорт), затем атрибуты существующих игр (после креативного этапа!)
4. **Обращение к «банку атрибутов»** — личный список атрибутов из предыдущих проектов

**Правило**: включать **вдвое больше атрибутов**, чем кажется нужным.

### Определение атрибута
Для практического использования нужно **уточнить определение**, привязав его к конкретной механике:
- «Сила» → «Максимальный вес бревна, который можно бросить с переворотом»
- Одно слово → конкретное, измеримое определение

### Критерии отбора
1. Каждый атрибут должен **использоваться** механикой
2. Атрибуты должны быть **тесно связаны с механиками**

### Группировка атрибутов
Иерархическая структура: базовые атрибуты (Сила, Ловкость, Здоровье, Скорость) → специфические подобно (вес для жима, слух, кровяное давление...).

**Для Gidede**: этот 4-этапный процесс → **алгоритм генерации атрибутов** в AI-системе. «Банк атрибутов» → база знаний, пополняемая с каждой анализируемой игрой.

### Ключевые правила организации данных

## Глава 11. Атрибуты в числах

### 6 принципов присвоения численных значений

| # | Принцип | Пояснение |
|---|---------|-----------|
| 1 | Числа соотносятся с вероятностью | Больше возможных исходов → больше числа (10 HP + 1D6 vs. 100 HP + 1D6) |
| 2 | Некоторые числа соотносятся с реальными единицами | Рост, вес, скорость — ожидания игроков |
| 3 | Для простоты вычислений числа должны быть небольшими | Чем чаще считает игрок → тем проще числа |
| 4 | Чем больше числа → тем больше детализация | Диапазон 1–10: 5 персонажей слишком грубо |
| 5 | Очень большие числа сбивают с толку | 34 863 298 − 456 321 = ? — люди плохо считают |
| 6 | Игроки ненавидят дроби | Целые числа для отображения; десятичные — только в фоне |

### Трюк с напряжением через числа

| Тип чисел | Эмоциональный эффект | Пример |
|-----------|---------------------|--------|
| «Лёгкие» числа (кратные, округлённые) | Спокойствие, уверенность | 20 HP − 5 − 5 − 5 = 5 (четверть, ясно) |
| «Сложные» числа (некруглые, дробные) | Напряжение, страх | 20 HP − 6 − 6 − 6 = 2 (больше красного на шкале!) |

**Для Gidede**: AI может **намеренно выбирать формат чисел** для создания нужных эмоций. Это уникальная формализация эмоционального дизайна через числа.

## Глава 12. Основы системного дизайна

### 1. Вес атрибутов

**Формула взвешенной суммы**:
```
Взвешенное значение = Необработанное значение × Вес
Итоговая оценка = Σ(Значение_i × Вес_i)
```

**Контринтуитивный аспект**: чем важнее атрибут → тем больше его вес → тем **меньше** будут необработанные значения у сбалансированных объектов.

Пример (точность вдвое важнее силы):
- Вес точности = 2.0, Вес силы = 1.0
- Лучник 1: Сила=10, Точность=10 → 10×1 + 10×2 = 30
- Лучник 2: Сила=20, Точность=5 → 20×1 + 5×2 = 30 (сбалансированы!)

### 2. DPS и взаимосвязанные атрибуты

**Формулы**:
```
Урон оружия × Атак в минуту = DPM (Damage Per Minute)
DPM / 60 = DPS
60 / Задержка (сек) = Атак в минуту
```

| Оружие | Урон | Атак/мин | DPM | DPS |
|--------|------|----------|-----|-----|
| Кинжал | 6 | 17 | 102 | 1.7 |
| Боевой топор | 14 | 7 | 98 | 1.6 |

### 3. Двоичный (бинарный) поиск

**Метод**: называть число в середине диапазона → исключить 50% вариантов → повторить.

| Вариантов | Макс. догадок |
|-----------|---------------|
| 2 | 2 |
| 4 | 3 |
| 16 | 5 |
| 64 | 7 |
| 256 | 9 |
| 1024 | 11 |

**Когда диапазон неизвестен — правило «удвой или уменьши вдвое»**: начать с любого числа, удваивать до «слишком много», затем бинарный поиск.

**Для Gidede**: алгоритм автоматической балансировки — **итеративный бинарный поиск** оптимальных значений атрибутов.

### 4. Система именования объектов

**Структура**: `Категория_Объект_Атрибут1_Атрибут2_Атрибут3`

**Стандартные категории**:
- Cha (Character), Npc, Bad (враги), Pow (Power-up), Wep (Weapon), Amr (Armor), Vhc (Vehicle)

**Стили**: CamelCase или подчёркивание — единый для команды.

### 5. Имена итераций

| Метод | Формат | Когда использовать |
|-------|--------|-------------------|
| Номер версии | `_01, _02, _03` | Мелкие итерации |
| Буква + номер | `_a01, _b01, _c01` | Буква = крупное изменение, число = мелкое |
| Специальные метки | `deleteme`, `deprecated`, `test` | Временные объекты |

### 6. Формула рукопожатий

**Количество уникальных попарных сравнений для N объектов**:
```
(N² − N) / 2 = уникальных комбинаций
```
Функция таблицы: `=COMBIN(N; 2)`

Примеры: 4 объекта → 6 комбинаций; 20 объектов → 190.

**Применения**: турниры, анимации победы, уникальные фразы, комбинированные способности.

## Глава 13. Балансировка диапазона, опорные точки данных и иерархический дизайн

### I. Балансировка диапазона (Range Balancing)

**Формула**:
```
((Max − Min) × %) + Min = численное значение
```

**Процесс**:
1. Определить Min и Max в шкале игрока
2. Вычесть Min из Max → диапазон
3. Каждому объекту присвоить процент (0–100%)
4. Применить формулу для получения значения в реальных единицах

**Разделение ответственности**:
- **Системный баланс** (Min, Max) — ведущий гейм-дизайнер — ощущения всей системы
- **Индивидуальный баланс** (%) — балансировщики — ощущения от конкретных объектов
- Изменение только Min/Max → мгновенно обновляет ВСЕ объекты, сохраняя пропорции

**Для Gidede**: формула балансировки диапазона — **ключевой алгоритм** для модуля балансировки. AI может автоматически пересчитывать все объекты при изменении Min/Max.

### II. Опорные точки данных (Fulcrum)

**Определение**: игровой объект как база для сравнения всех остальных. Часто не появляется в игре — технический инструмент.

**Процесс создания опорной точки**:
1. Задать каждому атрибуту значение в середине диапазона
2. Тестировать в наиболее распространённых ситуациях
3. Менять только один атрибут за итерацию
4. Тестировать в разных условиях

**Фиксация опорной точки**:
- После тестирования — зафиксировать, больше не менять
- Зафиксированная точка = измерительный эталон
- **Транзитивность**: если А сбалансирован с опорной, и Б сбалансирован с опорной → А ≈ Б
- Каждый объект тестируется **только против опорной точки**

**Прогрессия опорной точки**:
- Для каждого уровня — своя опорная точка
- Безопаснее всего начинать со среднего уровня (5-й из 9)
- Затем ослабить для минимального и усилить для максимального

**Для Gidede**: концепция опорной точки → **алгоритм балансировки**: AI создаёт «эталонный объект» и балансирует все остальные относительно него.

### III. Иерархический дизайн

**Принцип**: составить линейный список элементов от самых важных к наименее важным. При конфликте — менять тот, что **ниже** в иерархии.

**Пример иерархии (сверху вниз)**:
1. Общая концепция игры
2. Игровой движок
3. Платформа
4. Игровое управление / камера
5. Игровой ПИ
6. Игровой персонаж
7. Атрибуты
8. Опорный уровень
9. Опорный вражеский персонаж
10. Все другие персонажи
11. Усиления
12. Отдельные уровни
13. Награды макросистем
14. Звук / музыка / SFX

**Для Gidede**: иерархический дизайн → **система приоритетов** при автоматической балансировке. AI знает, что менять атрибуты легче, чем концепцию игры.

## Глава 14. Экспоненциальный рост и убывающая отдача

### Когда нужны: только в играх с механиками прогрессии

### Базовая формула экспоненциального роста
```
(Предыдущий шаг × Mult) + Add = Новый шаг
```

**Переменные**:
- **Init** — начальное значение (первый шаг)
- **Mult** — множитель итерации (>1 для роста)
- **Add** — аддитивное значение итерации (константа)

### Рекомендуемые стартовые значения

| Переменная | Значение |
|-----------|----------|
| Количество итераций | 100 |
| Init | 100 |
| Add | 10 |
| Mult | 1.02 |

### 5 проблем и их решения

| # | Проблема | Решение |
|---|----------|---------|
| 1 | Mult=1 → линейный рост | Mult > 1, но небольшой (1.02–1.10) |
| 2 | Большие Mult → астрономические числа | Малые значения (1.02–1.10) |
| 3 | Десятичные дроби в значениях | Столбец Display с ROUND |
| 4 | На ранних уровнях рост почти линеен | Увеличить Add |
| 5 | Слишком резкий скачок на ранних уровнях | Увеличить Init, чтобы Add составлял меньший % |

### Правило об итерациях
> Чем больше итераций, тем меньше должен быть множитель.

### Кривые экспоненциального роста в иерархии
- Изменение одной переменной → «эффект домино» по всей игре
- Графики экспоненциального роста = **высокий приоритет** в иерархии
- Следует **фиксировать на ранних этапах** разработки

**Для Gidede**: формула `(Prev × Mult) + Add` → **ядро генератора кривых прогрессии** в AI-системе. Переменные Init, Mult, Add — настраиваемые параметры.

## Глава 15. Анализ игровых данных

### Два основных метода анализа

1. **Обзорный анализ** — высокоуровневый обзор ключевых особенностей набора данных
2. **Сравнительный анализ** — глубокое сравнение двух конкретных объектов

### Инструменты обзорного анализа

| Метрика | Функция | Что выявляет |
|---------|---------|-------------|
| Среднее | AVERAGE | Базовая мера, но дезинформирует при выбросах |
| Медиана | MEDIAN | Центральное значение; сравнение со средним → асимметрия |
| Количество | COUNT | Размер набора; малые выборки → влияние выбросов |
| Мода | MODE | Наиболее частое значение |

### Концепция «Канарейки» (canary)
**Вычисление с заранее известным результатом** для проверки корректности данных:
- Сумма процентов = 100%
- AVERAGE = SUM / COUNT (двойная проверка)
- Общее количество элементов в каждом столбце

**Для Gidede**: «канарейки» → **автоматические валидаторы** в AI-системе. При генерации данных AI всегда включает проверочные вычисления.

## Глава 16. Макросистемы и вовлеченность игрока

### 6 категорий балансировки макросистем

| # | Метод | Суть | Когда подходит | Когда нет |
|---|-------|------|---------------|----------|
| 1 | Чистый баланс | Игра «честна» без поправок | Серьёзные соревнования | Получение удовольствия |
| 2 | Положительная обратная связь | «Богатые богатеют» | Выход из пата | Когда нужно наверстать |
| 3 | Отрицательная обратная связь | «Резиновая лента» | Казуальные игры | Серьёзные состязания |
| 4 | Динамическая настройка сложности (DDA) | ИИ корректирует невидимые параметры | Мобильные F2P, AAA экшен | Песочницы, открытые RPG |
| 5 | Многоуровневая сложность | Выбор: лёгкий/средний/сложный | Агентивность, свобода выбора | Ограниченные ресурсы |
| 6 | Перекрёстная настройка | Разные навыки для одной задачи | Большие игры со множеством механик | Балансировка сложности |

### Формула гандикапа (отрицательная обратная связь)
```
Гандикап = Максимальный счёт − Средний счёт игрока
```

### DDA — особые замечания
- DDA требует ≈50% времени разработки
- Игроки, покупающие усилители за реальные деньги в F2P, могут обнаружить обесценивание покупки из-за DDA → **«система запоздалой реакции DНС»**

**Для Gidede**: 6 методов → **алгоритм выбора стратегии балансировки** на основе профиля аудитории и типа игры.

## Глава 17. Тонкая настройка баланса, тестирование и решение проблем

### Определение баланса
**Баланс** — способ настроить данные так, чтобы у игроков возникло ощущение контроля (агентивности). Выбор не должен быть очевидным.

### 6 индикаторов общего баланса

1. **Время выбора** — мгновенный выбор = дисбаланс; раздумья = хороший знак
2. **Разногласия среди игроков** — защита разных вариантов = отличный баланс
3. **Равномерное распределение выбранных вариантов** — каждый выбирается хотя бы иногда
4. **Изменение условий** — игроки меняют тактики
5. **КНБ-комбинации** — у каждого варианта есть преимущество и недостаток
6. **Смена лидера** — частая смена лидирующего положения

### 5 этапов игрового тестирования

| Этап | Кто | Что делается |
|------|-----|-------------|
| 1. Минимальная работоспособность | Создатель | Проверка каждого изменения, опорной точки, группы, всей партии |
| 2. Тестирование баланса | Создатель | Опорная vs. сама себя → максимально удалённые объекты друг против друга |
| 3. QA | Независимая команда | Поиск багов |
| 4. Пользовательское тестирование | Целевая аудитория | Не сообщать цель теста; наблюдатель молчит; видео лица + экрана |
| 5. Бета/телеметрия | Реальные игроки | Data hooks (события), аналитик |

### Распределение времени гейм-дизайнера
> **Творчество — 10%, Реализация — 20%, Решение проблем — 70%**

### Алгоритм решения проблем (6 шагов)
1. Определить проблему (корень, не симптомы)
2. Исключить переменные (изоляция компонентов)
3. Придумать решения (мозговой штурм)
4. Пообщаться с командой (опора на иерархию)
5. Создать прототип и протестировать
6. Документировать изменения

## Глава 18. Системная коммуникация и психология

### Цикл коммуникации игры
```
Игра (изображения + звуки) → Интерпретация игроком → Действие игрока → 
Интерпретация игрой (по правилам) → Обратная связь (звук + визуал) → повтор
```

### Иерархия инструментов коммуникации (от наиболее к наименее эффективному)

| # | Инструмент | Эффективность | Пример |
|---|-----------|---------------|--------|
| 1 | Взаимодействие | ★★★★★ | Механика «привратника»: запертая дверь → попал стрелой → открылась |
| 2 | Демонстрация | ★★★★ | Видео, кат-сцена, NPC показывает |
| 3 | Рассказ | ★★★ | Звуковые инструкции |
| 4 | Письменное объяснение | ★★ | Текстовые подсказки |
| 5 | Подсказки | ★ | Иконография, визуальные намёки |
| 6 | Догадки | ✗ | Заставлять гадать и наказывать → избегать |

### 4 источника шума в коммуникации

1. **Непонятные правила** — плохо написанные или изложенные
2. **Технические ограничения** — аппаратные возможности
3. **Визуальные ограничения** — перегруженный UI
4. **Ограничения контроллера** — нестандартное управление

### Взаимность (reciprocity)
Игра и игрок строят «отношения»:
- **Переход границ** — слишком многого слишком рано → отторжение
- **Поверхностные отношения** — ничего нового ветерану → разочарование
- **Верный баланс** — постепенное нарастание сложности с вознаграждением → доверие

### Вознаграждение ожиданий
**Оптимистическое предубеждение**: игроки переоценивают вероятность благоприятных исходов.

**Правило**: занижать обещания и превышать ожидания.
- Награда «до 100 золотых» → получение 50 → разочарование
- Награда «не менее 40 золотых» → получение 50 → радость

**Для Gidede**: AI должен **автоматически формулировать обещания** с заниженными ожиданиями (нижняя граница), а не верхней.

## Глава 19. Вероятность

### Формула вероятности
```
P = Успешные варианты / Общее количество вариантов
```

### Нотация игральных костей
- **XDY** — X костей с Y гранями: 1D2 (монета), 1D6 (кубик), 2D6 (два кубика)

### Ключевые распределения

| Распределение | Форма | Где встречается |
|---------------|-------|----------------|
| Равномерное | Плоское | 1D6, монета, рулетка |
| Колоколообразное | Колокол | 2D6, 3D4 и любые множественные броски |
| Экспоненциальное | Длинный хвост | «Или выше» для костей, таблицы лута |
| Неравномерное | Произвольное | Таблицы лута с весами |

### Свойства колоколообразной кривой (2D6)
1. Крайние значения (2, 12) выпадают редко (<3%)
2. Центральное значение (7) = 16.67% — в 5 раз больше крайних
3. Центральное значение = количество граней + 1 (для 2D6: 6+1=7)
4. Шаг между соседними вероятностями = вероятность крайнего значения

### Серийная вероятность
```
P(n) = P(n-1) × P_one
P(НЕ) = 100% − P(событие)
```

### Весовые коэффициенты вероятности (vs. процентные)
- **Процентные**: P = процент/100; при изменении → эффект домино
- **Весовые**: P = вес / Σ весов; изменение одного веса автоматически пересчитывает все

### Ожидаемое значение (expected value)
```
EV = Σ(стоимость_события × вероятность_события)
```

### 5 атрибутов случайного события (профиль вероятности)

| # | Атрибут | Варианты |
|---|---------|----------|
| 1 | Пригодность для вычислений | Количественный / Элемент списка / Неопределённый |
| 2 | Измеримость | Дискретная / Непрерывная линейная / Непрерывная нелинейная |
| 3 | Тип случайности | Чистая удача / Зависимость от мастерства / Скрытое знание |
| 4 | Распределение | Равномерное / Колоколообразное / Экспоненциальное / Неравномерное |
| 5 | Зависимость | Независимый / Зависимый / Взаимоисключающий |

### 4 категории удачи в играх

| Категория | Описание | Тест |
|-----------|----------|------|
| Чистая удача | Решения не влияют | Можно убрать игрока без изменения результата? |
| Доминирование удачи | Решения влияют, но исход непредсказуем | Можно намеренно проиграть, но оптимальная стратегия не гарантирует победу? |
| Влияние удачи | Более способные выигрывают чаще | Нужны системы рейтинга (Эло, TrueSkill) |
| Чистое умение | Нет случайности | Шахматы, го, забег на 100 м |

### Настройка влияния удачи — 2 фактора

1. **Частота случайных событий** — интуитивно: больше → больше случайности, но **не всегда!**
2. **Степень влияния отдельных событий** — чем сильнее одно событие → тем больше роль удачи

**Парадокс**: для уменьшения влияния удачи не обязательно удалять случайные события — иногда добавление большего числа **малозначимых** событий выравнивает вероятность и усиливает роль мастерства.

**Для Gidede**: 5-атрибутный профиль вероятности → **формализованная модель** для AI при проектировании систем случайности. 4 категории удачи → **алгоритм классификации** и настройки влияния удачи.
