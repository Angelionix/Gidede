## 1.3.1 Единая концептуальная модель Gidede

### Архитектура модели

На основе анализа 17 книг выявлена **пятислойная модель геймдизайна**, в которой каждый слой соответствует уровню абстракции — от фундаментальных принципов до конкретных реализуемых алгоритмов:

```
┌─────────────────────────────────────────────────────┐
│  Слой 5: ПРОЦЕСС           (Как проектировать)      │
│  ─ Итеративный цикл, прототипирование, плейтест     │
├─────────────────────────────────────────────────────┤
│  Слой 4: ОПЫТ              (Что чувствует игрок)    │
│  ─ Эстетика, эмоции, мотивация, поток              │
├─────────────────────────────────────────────────────┤
│  Слой 3: ДИНАМИКА          (Как возникает опыт)     │
│  ─ Петли, экономика, эмерджентность, прогрессия     │
├─────────────────────────────────────────────────────┤
│  Слой 2: МЕХАНИКА           (Из чего состоит игра)  │
│  ─ Правила, ресурсы, действия, системы              │
├─────────────────────────────────────────────────────┤
│  Слой 1: ФУНДАМЕНТ         (На чём стоит дизайн)    │
│  ─ Определения, типологии, принципы                 │
└─────────────────────────────────────────────────────┘
```

### Слой 1: Фундамент

#### 1.1 Определения игры (спектр формализаций)

Спектр от концептуальных до строгих определений, выявленный из 5 источников:

| Автор | Определение | Ключевой акцент |
|-------|------------|-----------------|
| Сьюте (Кн. 17) | Игра — это структурированный конфликт | Конфликт как основа |
| Мейер (Кн. 17) | Игра — это система правил | Формальная система |
| Фуллертон (Кн. 5) | Игра — это структурированная игра с правилами и целями | Структура + цели |
| Шелл (Кн. 1, 2) | Игра — это средство создания опыта | Опыт первичен |
| Бургун (Кн. 17) | Игра — это система эндогенно значимых решений | Решения + значимость |

**Вывод для Gidede**: Определение игры для AI-системы должно быть **операциональным** — содержать проверяемые критерии. Рекомендуемое рабочее определение: *«Игра — это замкнутая формальная система с неопределённостью исхода, в которой игрок принимает эндогенно значимые решения, создавая эстетический опыт»*. Каждый элемент определения проверяем алгоритмически.

#### 1.2 Элементная модель (Тетрада)

Три уровня развития модели элементов игры:

**Базовая тетрада Шелла** (Кн. 1, 2): Механика, История, Эстетика, Технология — 4 равноправных элемента.

**Расширенная тетрада Бонда** (Кн. 17): 4 элемента × 3 уровня владения = матрица 4×3:

| | Механика | История | Эстетика | Технология |
|---|---------|---------|----------|------------|
| **Фиксированный** (создано разработчиком) | Правила, формулы | Сценарий, лор | Визуал, звук | Движок, платформа |
| **Динамический** (возникает при взаимодействии) | Эмерджентные стратегии | Эмергентный нарратив | Игровые моменты | Моды, настройки |
| **Культурный** (вне контроля разработчика) | Мета-игра, спидран | Фанфики, теории | Фан-арт, косплей | Моддинг, инструменты |

**Формальные элементы Фуллертон** (Кн. 5): Игроки, Цели, Процедуры, Правила, Ресурсы, Конфликт, Границы, Результат — модель данных для AI-генерации.

**Трёхуровневая модель Зубека** (Кн. 6): Механика → Геймплей → Опыт игрока — замена MDA с фокусом на дизайнера.

**Вывод для Gidede**: Использовать **матрицу 4×3 Бонда** как основной аналитический инструмент (расширяет Шелла, дополняется формальными элементами Фуллертона для модели данных).

Четыре модели, от интуитивных до научно обоснованных:

#### 1.4 Типологии механик

Три уровня классификации:

#### 2.2 Формальные модели механик

**Языковая метафора** (Кн. 6, 9): Объекты = существительные, Действия = глаголы, Правила = грамматика, Модификаторы = прилагательные/наречия — основа для NLP-генерации.

**Грамматика игры** (Кн. 9): Существительные = Атрибуты (данные), Глаголы = Механики (правила/код), Предложения = Микросистемы, Главы = Макросистемы, Книги = Игры — иерархическая модель.

**Пространство состояний** (Кн. 6): Состояние игры, Фактор ветвления, Плотность, Воспринимаемое пространство действий — формальный аппарат анализа.

**Дихотомия Юла** (Кн. 4): Игры эмерджентности (мало правил → много взаимодействий) vs Игры прогрессии (много правил → заданный путь). Большинство успешных игр комбинируют обе парадигмы.

**Типология эмерджентности Фромма** (Кн. 4): 4 уровня — Номинальная → Слабая → Множественная → Сильная.

#### 2.3 Machinations — визуальный язык моделирования (Кн. 4)

Полностью формализованный визуальный язык для моделирования игровых механик:

**Базовые узлы**: Pool, Source, Drain, Converter, Trader  
**Продвинутые узлы**: Register, Gate, Activator, Trigger, Delay, Queue, Action/Condition Labels, End Condition  
**Связи**: Ресурсные (сплошные стрелки), Состояний (пунктирные стрелки)  
**Искусственные игроки**: Автоматические агенты для симуляции тысяч прогонов

**Значение для Gidede**: Machinations — готовый формат данных для внутреннего представления механик. Может быть реализован как графовая структура с типизированными узлами и связями.

### Слой 3: Динамика

#### 3.1 MDA Framework и его расширения

**Классический MDA** (Hunicke, LeBlanc, Zubek): Mechanics → Dynamics → Aesthetics — аналитический путь (от игры к игроку).

**Обратный MDA** (Бонд, Кн. 17): Aesthetics → Dynamics → Mechanics — генеративный путь (от желаемого опыта к механикам). **Ключевой подход для AI-генерации**.

**Трёхуровневая модель Зубека** (Кн. 6): Механика → Геймплей → Опыт игрока — заменяет MDA с акцентом на дизайнера.

**8 типов эстетики (ЛеБланк)**: Чувственное, Фантазия, Нарратив, Вызов, Товарищество, Открытие, Выражение, Подчинение — из Кн. 2.

**Вывод для Gidede**: Двойной MDA-процесс:
1. **Генеративный** (Reverse MDA от Бонда): Определить эстетику → Вывести динамики → Сгенерировать механики из MechanicsDB
2. **Аналитический** (классический MDA): Проверить, какие эстетики порождают данные механики → Валидация

#### 3.2 Типология игровых систем (Engines/Economies/Ecologies)

**Источник**: Кн. 13 (Селлерс) — формальная классификация по двум осям:

| | Один ресурс | Конвертация ресурсов |
|---|-----------|---------------------|
| **Усиливающие петли** | **Двигатели (Engines)** | **Экономики (Economies)** |
| **Балансирующие петли** | *(редкий случай)* | **Экологии (Ecologies)** |

- **Двигатели**: Boosting (добавляют ресурсы, риск runaway) + Braking (удаляют ресурсы, предотвращают runaway). Пример: генерация золота → налог
- **Экономики**: Усиливающие петли с обменом/конвертацией. Валюты, рынки, встроенные двигатели. Пример: XP → уровни → новые способности → больше XP
- **Экологии**: Балансирующие петли с обменом/конвертацией. Метастабильность, resilience vs brittleness. Типы: инвентарь, бой, социальные

**Диагностика runaway** (Кн. 13): Усиливающий двигатель без тормозящего = runaway. Решение: добавить тормозящий двигатель (налоги, износ, расход).

**Диагностика deadlock/stall** (Кн. 13): Deadlock = ресурс цикла нужен для запуска. Stall = недостаточно ресурсов для продолжения.

**Вывод для Gidede**: Типология Engines/Economies/Ecologies — **основной классификатор** для модуля системного анализа. AI должен уметь: (1) классифицировать систему, (2) диагностировать runaway/deadlock, (3) предлагать коррекции.

#### 3.3 Петли обратной связи

**8 характеристик петли** (Кн. 4): Тип, Эффект, Инвестиция, Отдача, Скорость, Длительность, Косвенность, Определённость — формальная система описания.

**6 комбинаций (сумма × ОС)** (Кн. 7):
| | Положительная ОС | Отрицательная ОС |
|---|-----------------|-----------------|
| **Положительная сумма** | Экспоненциальный разрыв | «Качели» |
| **Нулевая сумма** | «Косичка» | Порочный круг |
| **Отрицательная сумма** | Саморазрушение | Стабильное равновесие |

**4 главные петли** (Кн. 13): (1) Петля модели игры, (2) Петля ментальной модели игрока, (3) Интерактивная петля, (4) Петля дизайнера.

**6 временных масштабов** (Кн. 13): Action/Feedback (мс–с) → Short-term Cognitive (с–мин) → Long-term Cognitive (мин–ч) → Social (ч–дни) → Emotional (ч–недели) → Cultural (недели–месяцы).

#### 3.4 Эмерджентность и второпорядочный дизайн

**Второпорядочный дизайн** (Кн. 13): Дизайнер создаёт пространство состояний, а не один путь; динамика эмерджентна из механики.

**Содержимое vs Системы** (Кн. 13): Content-driven (ручной контент, дорого) vs Systemic (эмерджентный контент, масштабируемо).

**Ключевой инсайт**: AI-система должна не генерировать «правильный» путь, а **создавать пространство возможностей** — второпорядочный дизайн как парадигма для генеративного модуля.

#### 3.5 Экономика игры

**Внутренняя экономика** (Кн. 4): 5 элементов (Источник, Сток, Пул, Конвертер, Торговец) + 5 структур (Петля, Блокировка, Равновесие, Дефицит, Профицит).

**5 уровней игровой экономики** (Кн. 5): Простой обмен → Сложный обмен → Простой рынок → Сложный рынок → Мета-экономика.

**Источники/Стоки/Хранилища/Потоки** (Кн. 13): Sources/Stocks/Sinks/Flows — формальная таксономия ресурсных элементов.

**Конструирование экономики** (Кн. 13): Источники (faucets) + Стоки (drains) = сбалансированная экономика. Патологии: инфляция, стагнация, арбитраж.

#### 3.6 Прогрессия

**7 типов кривых прогрессии** (Кн. 7): Тождественности, Линейная, Экспоненциальная, Логарифмическая, Треугольная, Пользовательская, Обфускации стоимости.

**6 типов кривых прогрессии** (Кн. 13): Линейная, Полиномиальная, Экспоненциальная, Логистическая (S-кривая), Кусочно-линейная, NAP.

**Формула экспоненциального роста** (Кн. 9): (Prev × Mult) + Add = New Step. Рекомендуемые: Mult 1.02–1.10.

**4 этапа прогрессии D&D** (Кн. 16): 1-4 (локальные угрозы), 5-10 (город/королевство), 11-16 (мировой масштаб), 17-20 (эпический).

**Макро-модель RPG** (Кн. 7): T часов → L уровней → L-1 переходов → ~L/T переходов/час → L/2 стадий контента → ≥3×(L/2) конфигураций противника.

**Эмерджентная прогрессия** (Кн. 4): Экономические фазы (начальная → рост → зрелость → завершение) — мост между эмерджентностью и прогрессией.

#### 3.7 Core Loop

**Петли взаимодействия** (Кн. 5, Cook): Ментальная модель → Решение → Действие → Правила → Фидбэк. Цепочка навыков: микро → мезо → макро → мета-петли.

**Геймплейные циклы** (Кн. 6): Микро (секунды) → Малый (1-2 мин) → Средний (5-10 мин) → Крупный (15-30 мин) → Макро (часы).

**5 вопросов кор-геймплея** (Кн. 10): Какой игровой цикл? В чём главный конфликт? Какие ресурсы? Как происходит взаимодействие? В чём цель игры?

**«30 секунд веселья»** (Кн. 7, от Halo): Core Loop = минимально значимая FUN-активность, мотивирующая продолжать.

**Game Loop D&D** (Кн. 16): Мастер описывает → Игроки действуют → Мастер рассказывает результаты → Возврат.

### Слой 4: Опыт

#### 4.1 Эстетика и эмоции

**8 типов эстетики** (ЛеБланк, Кн. 2): Чувственное, Фантазия, Нарратив, Вызов, Товарищество, Открытие, Выражение, Подчинение.

**5 качеств великой игры** (Кн. 10): Элегантность → Азарт → Глубина → Мотивация → Вовлечение.

**4 атрибута веселья** (Кн. 13): (1) Вызов, (2) Новизна, (3) Обучение/мастерство, (4) Эмоциональная связь.

**Кривая интереса** (Кн. 1, 2): Фрактальная модель pacing'а — крючок → нарастающие пики с отдыхом → кульминация → завершение. Три фрактальных уровня: игра целиком, уровень, отдельный вызов.

**Убийцы удовольствия** (Кн. 5): Микроменеджмент, застой, непреодолимые препятствия, произвольные события, предсказуемые пути.

#### 4.2 Потоковое состояние

**Канал потока** (Кн. 2, Чиксентмихайи): Баланс сложность ↔ навык; слишком сложно → фрустрация, слишком легко → скука.

**Матрица вызов/навык** (Кн. 5): Тревога/Поток/Контроль/Скука/Расслабление/Апатия.

**Кривая Йеркса-Додсона** (Кн. 13): Оптимальный уровень возбуждения = максимальная производительность.

**Нейрохимия вовлечения** (Кн. 13): Дофамин (предвкушение), Серотонин (статус), Окситоцин (связь), Эндорфины (преодоление).

#### 4.3 Нарратив

**Три термина** (Кн. 3): Сюжет (запланированная история), Повествование (процесс рассказа), Нарратив (полнота игрового опыта). Нарратив ≠ сюжет; нарратив присутствует всегда.

**Включённый vs эмергентный нарратив** (Кн. 3): Embedded = созданный сценаристами; Emergent = сформировавшийся в сознании игрока.

**Агентивность** (Кн. 3): Геймплейная (доступные действия) и сюжетная (влияние на сюжет). Три уровня: высокая, низкая, нулевая.

**Лудонарративный диссонанс** (Кн. 3, 4): Несоответствие сюжета и геймплея. Кн. 4 расширяет: Гармония (механика = нарратив), Ирония (механика ≠ нарратив — сатира), Диссонанс (механика ≠ нарратив — ошибка).

**4 структуры сюжета** (Кн. 3): Линейная, Разветвлённая, Открытая, Кольцевая.

**Кисётэнкэцу** (Кн. 3): Японская 4-частная структура — Введение, Развитие, Поворот, Развязка.

**Жемчужная нить** (Кн. 2): Кат-сцена ↔ свободный геймплей — мост между линейной историей и интерактивностью.

**Матрица квестов** (Кн. 3): 8 типов × 4 паттерна = 32 базовые комбинации для генерации.

#### 4.4 Мотивация

**5 типов мотивации** (Кн. 10): Победа (соревнование/достижения), Самовыражение (индивидуализация/отыгрыш), Связь (социализация/помощь), Погружение (опыт/история), Развитие (обучение/награды).

**Режимы подкрепления** (Кн. 6, оперантное научение): Фиксированное отношение, Фиксированный интервал, Переменное отношение (наиболее стойкое), Переменный интервал.

**Типы решений** (Кн. 5): Тривиальное, Безразличное, Дилемма, Значимое — классификатор качества выбора.

**Интересные решения** (Кн. 17): Обоюдоострые (и плюсы, и минусы) + Новизна + Последствия.

#### 4.5 Pacing и темп

**Матрица темпа 3×3** (Кн. 14): Интенсивность × Разнообразие × Время на трёх масштабах (микро/мезо/макро).

**Gates & Valves** (Кн. 14): Hard Gate (полная остановка), Soft Gate (замедление), Valve (область, закрывающаяся за игроком).

**Beats & Charts** (Кн. 14): График интенсивности по времени с чередованием высоких и низких точек.

**5 типов Gameplay Progression** (Кн. 8): Новая механика, Вариация, Комбинация, Инверсия, Удаление.

**«Музыка механик»** (Кн. 8): 7-шаговая последовательность введения механик: движение → +1 механика → +2 + комбо → +хазард → +враги → комбо → инверсия.

### Слой 5: Процесс

#### 5.1 Итеративный дизайн

**Playcentric Design Process** (Кн. 5): Цель опыта → Прототип → Плейтест → Оценка → Итерация.

**Базовый цикл разработки** (Кн. 10): 6 шагов — Задумка → Конкретизация → Мозговой штурм → Прототипирование → Тестирование → Итеративный поиск.

**4 главные петли** (Кн. 13): Модели игры, Ментальной модели игрока, Интерактивная, Дизайнера (мета-петля).

**Agile-мышление** (Кн. 17): Спринты, итерации, ретроспективы, MVP для игр.

**Правило цикла** (Кн. 1): Чем больше итераций тест→улучшение, тем лучше игра.

#### 5.2 Прототипирование

**Бумажное прототипирование** (Кн. 17): Каждый прототип = гипотеза, каждый плейтест = эксперимент.

**4 типа цифровых прототипов** (Кн. 5): Механический, Эстетический, Кинестетический, Технологический.

**8 вопросов прототипирования** (Кн. 11): Габариты, метрика механик, среда для AI, доп. механики, камера, качество контента, инструментарий, тест на прочность.

**4-фазный процесс производства** (Кн. 11): Планирование → Играбельный прототип → Прототип геометрии → Финальная сборка.

**8 прототипов как жанровые паттерны** (Кн. 17): Apple Catcher, Physics Launcher, SHMUP, Card, Card MP, Word, RPG — каждый описывает паттерн реализации жанра.

#### 5.3 Плейтестирование

**RITE-метод** (Кн. 5): 4-5 тестировщиков → тест → немедленный фикс → повторный тест → итерация.

**26 правил плейтестирования** (Кн. 5): от «Ask open questions» до «Zero in on the core experience».

**Структурированный опросник** (Кн. 10): 3 понравившихся, 3 не понравившихся, что непонятно, что изменить, что оставить.

**Принцип «измени одно правило»** (Кн. 17): После каждой пробной игры — изменять только что-то одно.

**Научный метод** (Кн. 9): 8 этапов — Формулировка вопросов → Сбор информации → Гипотеза → Эксперимент → Анализ → Интерпретация → Публикация → Повторное тестирование.

#### 5.4 Документация

**Модульные GDD** (Кн. 1): Краткий GDD, детальный GDD, обзор истории, тех. документ, Art Bible и т.д.

**GDD из 38 секций** (Кн. 8): Полный шаблон дизайн-документа от обложки до приложения.

**One-Sheet** (Кн. 8): 8 полей — Название, платформа, аудитория, рейтинг, описание сюжета, описание геймплея, 3 уникальные фичи, конкуренты.

**3 уровня документации** (Кн. 12): Техническое предложение (5-6 стр.) → Эскизный проект → Полная документация.

**11 типов нарративной документации** (Кн. 3): Бриф, Синопсис, Расширенный синопсис, Сторилайн, Библия персонажей, Блок-схемы, Таблицы, Вики, Поэпизодный план, ТЗ для арта, ГДД.

**Концепт-документ** (Кн. 13): 3 раздела — Высокоуровневая концепция (название, заявление 140 символов, жанр, аудитория, USP) → Описание продукта → Детальный дизайн.

## 1.3.3 Анализ пробелов

### Пробелы в книгах vs потребности программы

#### Пробел 1: Отсутствие формальной модели генерации концепции

**Что есть**: Triangle of Weirdness (Кн. 8), 8 фильтров идеи (Кн. 1), Box Cover Method (Кн. 8), 5 вопросов кор-геймплея (Кн. 10)  
**Чего нет**: Алгоритма, который из входных данных (жанр, ЦА, платформа) генерирует **завершённую** концепцию игры — включая Core Loop, ключевые механики, эстетику и USP  
**Решение для Gidede**: Создать **Generator Pipeline**:
1. Вход: Жанр + ЦА + Ограничения
2. Reverse MDA: Определить эстетику из модели Йи/Big Five
3. Выбор механик из MechanicsDB (7-шаговый алгоритм из Кн. 15)
4. Конструирование Core Loop из петель Кн. 6 + шаблонов Кн. 5
5. Валидация: 113 линз Шелла + Triangle of Weirdness + 8 фильтров

#### Пробел 2: Нет интегрированной модели «Баланс → Экономика → Прогрессия»

**Что есть**: 7 типов баланса (Кн. 7), Типология систем (Кн. 13), Кривые прогрессии (Кн. 7, 9, 13), Machinations (Кн. 4)  
**Чего нет**: Единого пайплайна, который связывает балансировку механик, конструирование экономики и настройку прогрессии в один процесс  
**Решение для Gidede**: Создать **Balance-Economy-Progression Pipeline**:
1. Определить тип системы (Engine/Economy/Ecology — Кн. 13)
2. Смоделировать через Machinations-нотацию (Кн. 4)
3. Настроить кривые прогрессии (Кн. 7 формулы + Кн. 9 параметрическая модель)
4. Проверить баланс через формулу диапазона (Кн. 9) + Q-фактор (Кн. 12) + золотое правило (Кн. 12)
5. Симуляция через искусственных игроков (Кн. 4)

#### Пробел 3: Нет модели «Генерация уровня от концепции до реализации»

**Что есть**: 9 навигационных инструментов (Кн. 11), 7 методов руководства (Кн. 17), 5 структур MP-карт (Кн. 14), «Основа + Изюминка» (Кн. 11), «Музыка механик» (Кн. 8)  
**Чего нет**: Алгоритма, который из описания механик и целей уровня генерирует структуру уровня с навигацией, боем и темпом  
**Решение для Gidede**: Создать **Level Generator Pipeline**:
1. Вход: Core Loop + механики + целевой опыт
2. Концепция уровня: «Основа + Изюминка» (Кн. 11)
3. Планировка: боевая (Кн. 14 Combat Fronts) или MP (Кн. 14 5 структур)
4. Навигация: 7 методов руководства (Кн. 17) + 9 инструментов (Кн. 11)
5. Темп: Матрица 3×3 (Кн. 14) + «Музыка механик» (Кн. 8)
6. Валидация: 15-пунктный чек-лист LD (Кн. 14)

#### Пробел 4: Нет модели генерации нарратива от механик

**Что есть**: Матрица квестов (Кн. 3), Валидатор лудонарративного диссонанса (Кн. 3), Теория коммуникации (Кн. 4), Story Machine (Кн. 2)  
**Чего нет**: Алгоритма, который из набора механик и эстетических целей генерирует структуру нарратива (персонажи, сюжет, квесты)  
**Решение для Gidede**: Создать **Narrative Generator Pipeline**:
1. Определить тип нарратива: Embedded vs Emergent (Кн. 3)
2. Для Embedded: Структура сюжета (4 типа, Кн. 3) + Кисётэнкэцу + Жемчужная нить (Кн. 2)
3. Персонажи: 6 типов (Кн. 3) + Циркумплекс (Кн. 2)
4. Квесты: Матрица 8×4 = 32 комбинации (Кн. 3)
5. Валидация: Лудонарративный диссонанс (Кн. 3) + Гармония/Ирония/Диссонанс (Кн. 4)

#### Пробел 5: Нет единой модели валидации геймдизайна

**Что есть**: 113 линз (Кн. 1), AI-чек-листы (Кн. 10, 12, 14, 15, 16, 17), Q-фактор (Кн. 12), Золотое правило (Кн. 12)  
**Чего нет**: Интегрированного валидатора, который проверяет все аспекты дизайна — от механик до опыта, от баланса до нарратива  
**Решение для Gidede**: Создать **Universal Design Validator** на основе объединения:
1. 113 линз Шелла (Кн. 1, 2) — самый полный каталог вопросов
2. AI-чек-листы из книг 10, 12, 14, 15, 16, 17 — специализированные проверки
3. Q-фактор (Кн. 12) — выявление мёртвых компонентов
4. Валидатор лудонарративного диссонанса (Кн. 3) — согласованность
5. Золотое правило баланса (Кн. 12) — нет случайной оптимальной стратегии

#### Пробел 6: Нет модели генерации документации от дизайна

**Что есть**: GDD из 38 секций (Кн. 8), One-Sheet (Кн. 8), 3 уровня документации (Кн. 12), 11 типов нарративной документации (Кн. 3)  
**Чего нет**: Алгоритма, который из проектных данных автоматически генерирует структурированный GDD нужного формата  
**Решение для Gidede**: Создать **GDD Generator**:
1. Вход: Все данные проекта из предыдущих модулей
2. Выбор формата: One-Sheet / Ten-Pager / Full GDD / Concept Doc
3. Автозаполнение секций из MechanicsDB + Core Loop + Balance Data + Narrative
4. Валидация полноты через шаблоны (Кн. 8, 12)

#### Пробел 7: Нет практической модели AI-интеграции

**Что есть**: Обратный MDA (Кн. 17), MechanicsDB (Кн. 15), Machinations (Кн. 4)  
**Чего нет**: Спецификации, что именно генерирует AI (текст, структуры, формулы), а что — алгоритмы (формулы, симуляции, валидация)  
**Решение для Gidede**: Создать **AI/Algorithm Split Model**:
- **AI генерирует**: Концепции, нарратив, описания, диалоги, вопросы линз, рекомендации
- **Алгоритмы вычисляют**: Баланс, стоимость, кривые, вероятности, симуляции, валидация
- **Гибрид**: Выбор механик (AI предлагает из MechanicsDB, алгоритм проверяет совместимость), Core Loop (AI проектирует структуру, алгоритм проверяет петли)

#### Пробел 8: Нет модели монетизации и Retention

**Что есть**: Аналитические KPIs (Кн. 13: Acquisition, Retention, Conversion), 5 уровней экономики (Кн. 5)  
**Чего нет**: Конкретных моделей монетизации (F2P, Premium, Подписка, IAP), формул Retention, систем LiveOps, A/B-тестирования  
**Решение для Gidede**: Дополнить через веб-исследование + практические источники:
- Модели монетизации из мобильного геймдева
- Формулы LTV, CAC, ROAS
- Системы LiveOps (Battle Pass, Seasons, Events)
- A/B-тестирование и аналитика

#### Пробел 9: Нет конкретных UX/UI-паттернов для инструмента геймдизайнера

**Что есть**: UI-валидатор (Кн. 10: Понятно/Легко найти/Приятно), Профиль аудитории (Кн. 9)  
**Чего нет**: Конкретных UX-паттернов для интерактивного инструмента геймдизайна — визуальные редакторы, дашборды, мастера, чат-интерфейсы  
**Решение для Gidede**: Определить в Фазе 2.5 на основе анализа аналогов (Articy Draft, Machinations, GameMaker)

#### Пробел 10: Нет практических кейсов применения алгоритмов

**Что есть**: Примеры балансировки MTG (Кн. 7), Кейс Pirates of the Caribbean VR (Кн. 2), Кейс Lunar Colony (Кн. 4)  
**Чего нет**: Систематической библиотеки кейсов «входной запрос → результат генерации» для обучения и валидации AI  
**Решение для Gidede**: Создать **Case Library** в Фазе 2 из 10-15 кейсов разных жанров, каждый с полным циклом от концепции до GDD.
