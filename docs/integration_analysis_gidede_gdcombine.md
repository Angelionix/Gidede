## 1. Обзор проектов

### Gidede — Game Design AI System

**Суть**: Интеллектуальная система для генерации и помощи в создании геймдизайна. Использует анализ 17 книг по геймдизайну, веб-исследования и AI для создания «Библии геймдизайна», формализации алгоритмов и построения веб-приложения — AI-ассистента геймдизайнера.

| Характеристика | Описание |
|---------------|----------|
| Стадия | Исследование (Фаза 1 из 4) |
| Технологический стек | Не определён (планируется Next.js) |
| Ядро | AI-first подход: генерация концепций, механик, баланса, GDD |
| Данные | 17 книг по геймдизайну (845 МБ PDF), веб-исследования |
| Результат | Библия геймдизайна → Алгоритмы → Веб-приложение |

### GDCombine / GBE — Game Blueprint Engine

**Суть**: Single Source of Truth (SSOT) генератор документации для геймдизайна. Централизует все сущности геймдизайна (Blueprints) в структурированное, типизированное, валидируемое JSON-хранилище. Killer workflow: выбрал пресет RPG → заполнил формы → проверил линтером → сгенерировал GDD → экспортировал в Unity — за 5 минут.

| Характеристика | Описание |
|---------------|----------|
| Стадия | Рабочий продукт v2.2 (23+ итераций) |
| Технологический стек | Python/FastAPI + Vue.js/TypeScript + JSON + SQLite FTS5 |
| Ядро | SSOT: структурированные данные → документы, код, изображения |
| Данные | 15 типов Blueprint с Pydantic-валидацией |
| Результат | Полнофункциональное приложение (Web + Desktop + PWA) |

## 3. Варианты интеграции

### Вариант A: Gidede как плагин для GDCombine

**Концепция**: Gidede реализуется как плагин для GBE, используя существующую плагинную архитектуру (5 интерфейсов расширения).

#### Архитектура

```
GDCombine (GBE) — основное приложение
├── Встроенные плагины (6 шт.)
│   ├── Image Gen
│   ├── Story
│   ├── Quest System
│   ├── Game Loops
│   ├── Balancing
│   └── Level Design
├── GIDED E PLUGIN ← НОВЫЙ
│   ├── BlueprintTypeProvider
│   │   └── Новые типы: MDAModel, LensAnalysis, MachinationsDiagram
│   ├── DocumentTemplateProvider
│   │   └── Шаблоны: Библия геймдизайна, Анализ линз, Machinations-отчёт
│   ├── LinterRuleProvider
│   │   └── Правила: MDA-валидация, проверка линз Шелла, эмерджентность
│   ├── EngineExporterProvider
│   │   └── Экспорт: Machinations → JSON для симуляции
│   └── PresetProvider
│       └── Пресеты: Жанровые конфигурации на основе 17 книг
```

#### Преимущества
- ✅ Не нужно строить инфраструктуру с нуля (CRUD, UI, AI-провайдеры, экспорт — уже есть)
- ✅ Немедленный доступ к 15 типам Blueprint и их данным (контекст для AI)
- ✅ Пользователи GBE получают AI-генерацию геймдизайна без смены инструмента
- ✅ Маркетплейс GBE — канал дистрибуции
- ✅ Быстрый MVP — можно сделать за 2-4 недели

#### Недостатки
- ❌ Ограничение архитектурой GBE (Python/FastAPI + Vue.js — не Next.js)
- ❌ Gidede теряет независимость — зависит от развития GBE
- ❌ JSON-хранилище GBE — не лучшая основа для AI-моделей (нет векторного поиска, нет БД)
- ❌ Синхронный I/O в GBE блокирует event loop — проблемы при тяжёлых AI-запросах
- ❌ Нет авторизации в GBE — безопасность под вопросом

#### Оценка реализуемости: 🟢 Высокая (GBE-плагины работают)

### Вариант B: GDCombine как модуль данных для Gidede

**Концепция**: Gidede — основное приложение, а GBE используется как «бэкенд данных» — структурированное хранилище Blueprint и генератор документов.

#### Архитектура

```
Gidede — основное приложение (Next.js)
├── AI-модули
│   ├── Генератор концепций (MDA, линзы, Machinations)
│   ├── Генератор механик (паттерны Adams & Dormans)
│   ├── Модуль балансировки (симуляция)
│   ├── Нарративный модуль
│   └── GDD-генератор
├── GDCombine API Client ← ИНТЕГРАЦИЯ
│   ├── Blueprint CRUD (через REST API GBE)
│   ├── Document Generation (через API GBE)
│   ├── Linter (через API GBE)
│   └── Export (через API GBE)
└── UI (собственный, на Next.js)
```

#### Преимущества
- ✅ Gidede контролирует UX и AI-пайплайн
- ✅ GBE предоставляет готовую структуру данных и валидацию
- ✅ Можно заменить JSON-хранилище GBE на PostgreSQL/векторную БД
- ✅ Machinations-визуализация — уникальная фича Gidede
- ✅ Гибкость: Gidede может расширять AI без ограничений GBE

#### Недостатки
- ❌ Нужно разрабатывать UI с нуля (GBE уже имеет 69 компонентов)
- ❌ Два развернутых сервиса → сложнее деплой
- ❌ Дублирование AI-логики (GBE уже имеет AI, Gidede будет иметь свою)
- ❌ REST API GBE (269 эндпоинтов) — не все оптимизированы для AI-потребления

#### Оценка реализуемости: 🟡 Средняя (нужна разработка UI)

│   ├── Document Generator (11 шаблонов GBE + Библия геймдизайна от Gidede)
│   ├── Machinations Engine ← НОВЫЙ (симуляция механик)
│   ├── Linter (3 уровня GBE + MDA/линзы от Gidede)

│   ├── AI Assistant (расширенный от Gidede)
│   ├── Machinations Visualizer ← НОВЫЙ
│   ├── MDA Analyzer ← НОВЫЙ
│   ├── Lens Checklist ← НОВЫЙ
│   └── Dashboard/Analytics (от GBE)
└── AI Knowledge Base ← НОВЫЙ
    ├── 17 книг → векторная БД (embeddings)
    ├── Библия геймдизайна → структурированные знания
    └── Фреймворки: MDA, Линзы, Machinations, Кривые интереса

#### Преимущества
- ✅ Один инструмент — максимум функциональности
- ✅ Нет дублирования между проектами
- ✅ Данные и AI работают в единой среде
- ✅ Пользователю не нужно переключаться между инструментами

#### Недостатки
- ❌ Огромный объём работы по слиянию (два разных стека)

- ❌ Потеря фокуса: «инструмент для всего» часто = «ни для чего конкретно»

#### Оценка реализуемости: 🔴 Низкая (слишком много работы, высокие риски)

### Вариант D: Два независимых проекта с API-мостом

**Концепция**: Каждый проект развивается независимо, но между ними настраивается двусторонний API-мост для обмена данными.

#### Архитектура

```
Gidede (Next.js) ←→ API Bridge ←→ GDCombine (Python/FastAPI)
                         │
                    Sync Service
                    ├── Gidede → GBE: AI-генерированные Blueprint
                    ├── GBE → Gidede: Структурированные данные проекта
                    ├── Gidede → GBE: Результаты анализа (линзы, MDA, баланс)
                    └── GBE → Gidede: Документы и экспорт
```

#### Конкретные API-интеграции

| Направление | Данные | Формат |
|-------------|--------|--------|
| Gidede → GBE | Сгенерированные концепции игры | JSON Blueprint |
| Gidede → GBE | Анализ MDA-фреймворка | JSON MDAModel |
| Gidede → GBE | Результаты проверки линз Шелла | JSON LensReport |
| Gidede → GBE | Machinations-модели механик | JSON MachinationsDiagram |
| Gidede → GBE | Рекомендации по балансу | JSON BalanceReport |
| GBE → Gidede | Все Blueprint проекта | REST API / JSON |
| GBE → Gidede | Результаты линтера | JSON LintReport |
| GBE → Gidede | Сгенерированные документы | PDF/DOCX |
| GBE → Gidede | Unity/Godot экспорт | ZIP архив |

#### Преимущества
- ✅ Каждый проект развивается со своим темпом и стеком
- ✅ Чёткое разделение ответственности: Gidede = AI/анализ, GBE = данные/документы/экспорт
- ✅ Можно оптимизировать каждый проект независимо
- ✅ Пользователь может использовать оба или только один
- ✅ Наименьший риск архитектурных проблем

#### Недостатки
- ❌ Пользователю нужно два инструмента
- ❌ Синхронизация данных — потенциальный источник багов
- ❌ Дублирование некоторых функций (AI есть в обоих)
- ❌ Два деплоя, две инфраструктуры

#### Оценка реализуемости: 🟢 Высокая (REST API уже есть в GBE)

## 4. Рекомендуемая стратегия

### Фаза 1 (немедленно): Вариант A — Gidede как плагин GBE

**Почему**: Это самый быстрый путь к работающему продукту. GBE — готовое приложение с UI, данными, AI, документами, экспортом. Gidede привносит уникальную ценность — глубокий AI-анализ на основе фреймворков из 17 книг.

**Конкретные шаги**:

1. **Создать плагин `gide-de-frameworks`** для GBE:
   - `BlueprintTypeProvider`: типы `MDAModel`, `LensChecklist`, `MachinationsDiagram`, `BalanceAnalysis`
   - `DocumentTemplateProvider`: шаблоны «Библия геймдизайна», «Анализ линз Шелла», «Machinations-отчёт»
   - `LinterRuleProvider`: правила MDA-валидации, проверка эмерджентности, обнаружение лудонарративного диссонанса
   - `PresetProvider`: пресеты на основе 17 книг (RPG, Strategy, FPS, Puzzle, Sandbox)

2. **Расширить AI-промпты GBE** знаниями из книг:
   - Добавить контекст из анализа Шелла (113 линз) в `PromptBuilder`
   - Добавить паттерны Adams & Dormans в генерацию механик
   - Добавить нарративные инструменты Андриановой/Яковлевой в Story Plugin

3. **Добавить Machinations-визуализатор**:
   - Использовать D3.js (уже есть в GBE) для рендеринга Machinations-диаграмм
   - Связать с Blueprint-данными для автоматического построения моделей экономики

### Фаза 2 (среднесрочно): Вариант D — API-мост

**Почему**: Когда Gidede станет достаточно зрелым как самостоятельный AI-движок, позволит использовать его независимо от GBE.

**Конкретные шаги**:

1. Реализовать Gidede как отдельный Next.js-сервис с REST API
2. Создать API Bridge: GBE → Gidede (данные проекта) и Gidede → GBE (AI-результаты)
3. Пользователь может выбрать: работать только в GBE, только в Gidede, или в обоих

### Фаза 3 (долгосрочно): Оценить Вариант C

**Почему**: Когда оба проекта созреют, можно оценить целесообразность полного слияния. Но сейчас это преждевременно.

## 5. Конкретные точки интеграции

### 5.1 AI-провайдеры

GBE уже имеет мультипровайдерную AI-систему с 5 провайдерами и fallback chain. Gidede может:
- Использовать ту же систему (через плагин)
- Добавить специализированные промпты на основе фреймворков из книг
- Расширить `PromptBuilder` GBE контекстом из «Библии геймдизайна»

### 5.2 Blueprint-данные как контекст для AI

15 типов Blueprint GBE — идеальный контекст для AI Gidede:
- `character` → AI может анализировать баланс характеристик
- `quest` → AI может проверять нарративную связность
- `skill` → AI может анализировать дерево навыков на основе MDA
- `faction` → AI может моделировать политические системы

### 5.3 Линтер GBE + фреймворки Gidede

Трёхуровневый линтер GBE можно расширить:
- **L1 (структурный)** — уже есть в GBE
- **L2 (референциальная целостность)** — уже есть в GBE
- **L3 (детекция паттернов)** — уже есть в GBE (AI-детекция)
- **L4 (фреймворк-валидация)** ← НОВЫЙ от Gidede:
  - MDA-проверка: есть ли у игры чёткие механики, динамики и эстетика?
  - Линзы Шелла: автоматический опрос по релевантным линзам
  - Machinations-анализ: есть ли некомпенсированные положительные петли?
  - Эмерджентность: достаточна ли сложность системы для эмерджентного геймплея?

### 5.4 Machinations + D3.js

GBE уже использует D3.js для графов связей. Machinations-визуализация — естественное расширение:
- Узлы Machinations → D3.js nodes
- Связи ресурсов → D3.js links
- Симуляция → D3.js animation

### 5.5 Документация

11 шаблонов GBE + шаблоны Gidede:
- GBE: GDD, One-Pager, Pitch Deck, Art Bible, Quest Document, Story Document, Game Loop Analysis, Balance Report, Level Design Document, NPC Bible, Dialogue Script
- Gidede: Библия геймдизайна, MDA-анализ, Чек-лист линз Шелла, Machinations-модель экономики, Кривая интереса, Анализ эмерджентности

## 6. Технические рекомендации

### 6.1 Приоритетные исправления в GBE для интеграции

| Приоритет | Проблема | Решение |
|-----------|----------|---------|
| **P0** | Синхронный файловый I/O | Заменить `json.load/dump` на `aiofiles` + `orjson` |
| **P0** | Нет авторизации | Добавить JWT-авторизацию (FastAPI + python-jose) |
| **P1** | Нет кэширования | Добавить Redis или in-memory LRU cache |
| **P1** | Нет фоновой очереди | Добавить Celery или arq для AI-запросов |
| **P2** | JSON вместо БД | Миграция на PostgreSQL + SQLAlchemy (когда потребуется масштабирование) |

### 6.2 Новые Blueprint-типы от Gidede

```python
class MDAModel(BaseModel):
    """MDA Framework модель игры"""
    mechanics: List[str]       # Механики
    dynamics: List[str]        # Динамики
    aesthetics: List[str]      # Эстетики (8 типов Hunicke)
    feedback_loops: List[FeedbackLoop]

class LensChecklist(BaseModel):
    """Чек-лист линз Шелла"""
    game_id: str
    relevant_lenses: List[int]  # Номера релевантных линз
    checks: List[LensCheck]     # Результат проверки каждой линзы
    score: float                # Общий счёт

class MachinationsDiagram(BaseModel):
    """Machinations-модель экономики"""
    nodes: List[MachinationsNode]
    connections: List[MachinationsConnection]
    artificial_players: List[ArtificialPlayerStrategy]
    simulation_results: Optional[SimulationResults]

class BalanceAnalysis(BaseModel):
    """Анализ баланса на основе Adams & Dormans"""
    feedback_profiles: List[FeedbackProfile]  # 7 характеристик × каждая петля
    patterns_detected: List[str]              # Названия паттернов из библиотеки
    imbalance_warnings: List[ImbalanceWarning]
    recommendations: List[str]
```

### 6.3 API-интеграция

Для Варианта D (API-мост), Gidede должен exposing следующие эндпоинты:

## 7. Итоговая рекомендация

### Краткий вердикт

**Рекомендуемый путь**: Вариант A (Gidede как плагин GBE) → Вариант D (API-мост)

**Обоснование**:

1. **GBE — уже работающий продукт** с 23+ итерациями. Он решает 80% задач по структурированию данных и генерации документации. Нет смысла дублировать эту работу.

2. **Gidede — уникальная ценность** — глубокий AI-анализ на основе формальных фреймворков (MDA, линзы Шелла, Machinations, кривые интереса). Этого нет ни в одном существующем инструменте.

3. **Симбиоз**: GBE даёт структуру и данные, Gidede даёт интеллект и анализ. Вместе они создают продукт, которого не существует на рынке — AI-first геймдизайн-тул с формальными фреймворками.

4. **Практичность**: Плагин для GBE можно создать за 2-4 недели. Отдельное приложение Gidede с нуля — минимум 3-6 месяцев.
