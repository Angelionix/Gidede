## 1. Общая характеристика

«Колода геймдизайнера» — это физический карточный инструмент, содержащий **127 карт** с описаниями игровых механик компьютерных и видеоигр. Каждая карта описывает одну механику с определением, вариантами применения и примерами из реальных игр. Колода предназначена для: (1) декомпозиции существующих игр на механики, (2) генерации идей новых игр через случайные комбинации механик, (3) группового брейншторма, (4) анализа и ограничения механического пространства игры.

**Структура колоды**:
- **Основная часть**: 99 карт (синяя рубашка), 14 групп механик
- **Расширенная часть**: 28 карт (зелёная рубашка), 1 дополнительная группа + расширения
- **Итого**: 127 карт, 15 групп механик

**Уникальная ценность для Gidede**: Это единственный инструмент в библиотеке проекта, который представляет **полный каталог игровых механик в формате, готовом к алгоритмической обработке**. В отличие от книг, описывающих механики через нарративные модели и фреймворки, Колода даёт механики как дискретные, комбинируемые единицы — что напрямую соответствует задаче генеративного модуля Gidede. Колода фактически представляет собой готовую таксономию, которую можно формализовать в базу данных механик с атрибутами и связями.

## 3. 5 вариантов использования колоды (методологии)

### Вариант 1: Разбор игры по механикам
- **Процесс**: Выкладывать карты с механиками, присутствующими в анализируемой игре
- **Дополнение**: Найти механики, которые есть в игре, но отсутствуют в колоде
- **Развитие**: Придумать игру с теми же механиками в другом жанре
- **Применение в Gidede**: Режим «Анализ существующей игры» — автоматическая генерация механического профиля игры

### Вариант 2: Придумывание игры
- **Процесс**: Взять 3 карты из основных + 3 из дополнительных; заполнить лист-геймификатор
- **Ограничения**: Перевёрнутая карта = запрещённая механика
- **Варьирование**: Изменение числа карт для сложности
- **Применение в Gidede**: Режим «Генератор концепции» — алгоритмический выбор и комбинирование механик

### Вариант 3: Полёт фантазии
- **Процесс**: 10 случайных карт → придумать игру без ограничений
- **Инструмент**: Лист-геймификатор для фиксации идей
- **Применение в Gidede**: Режим «Random Game Jam» — генерация случайных комбинаций механик с AI-описанием

### Вариант 4: Групповой брейншторм
- **Фаза 1**: Участники по очереди выкладывают карты механик
- **Фаза 2**: Совместное придумывание игры по выложенным механикам
- **Расширение**: Механизм запрета (переворот) и «убийство» чужих карт ценой своей
- **Применение в Gidede**: Мультиагентная генерация — несколько AI-агентов «дискутируют» о механиках

### 5.3. Модель совместимости механик

На основе анализа описаний карт можно выделить следующие типы связей:

**Синергии** (механики, усиливающие друг друга):
- Стелс + Бесшумное оружие + Ночное видение → полный стелс-пакет
- Очки опыта + Древо технологий + Характеристики → RPG-прогрессия
- Волны врагов + Строительство + Сбор ресурсов → tower defense
- Инвентарь + Крафтинг + Сбор ресурсов → survival-craft
- Броня + Укрытия + Блок атак → оборонительный шутер
- Воровство + Стелс + Без убийств → стелс-дипломат
- Экономика + Торг + Сбор ресурсов → экономический симулятор
- Мультицели + Альтернативы + Варианты решения → открытый мир
- Туман войны + Органы чувств врагов + Стелс → тактический стелс
- Мораль + Взаимодействие NPC + Наказание игрока → моральная система

**Конфликты** (механики, противоречащие друг другу):
- Без интерфейса + Показ цели → противоречие (нет HUD, но цель показана)
- Смерть навсегда + Читы → перманентная смерть бессмысленна с читами
- Без убийств + Орды врагов → сложно реализовать без убийств
- Без персонажа + Обмундирование → нет персонажа = нет экипировки
- Бесконечная игра + Ограничение длины → взаимоисключающие

**Нейтральные** (могут сочетаться с большинством механик):
- Сохранение/загрузка, Пауза, Обучение, Подсказки, Скины

```

  - Обязательны: минимум 1 из {Здоровье, Достижения и очки}

ШАГ 2: Выбор боевых механик (Группы 4, 8)
  - Если выбрана «Враги» → подтянуть из Группы 4
  - Если шутер → Броня + Запас патронов + Укрытия
  - Если стелс → Бесшумное оружие + Ночное видение + Без убийств

ШАГ 3: Выбор прогрессии (Группы 9, 2)
  - Если RPG → Очки опыта + Перки + Характеристики + Древо технологий
  - Если action → Прокачка оружия + Обмундирование

ШАГ 4: Выбор пространственных механик (Группы 3, 5, 11)
  - Если открытый мир → Альтернативы + Мультицели + Карта мира
  - Если линейный → Ограничение длины + Двери + Варианты решения

ШАГ 5: Выбор социальных/информационных (Группа 7)
  - Если мультиплеер → Взаимодействие + Сетевой мультиплеер
  - Если одиночная → Информация о мире + Катсцены

ШАГ 6: Валидация совместимости
  - Проверка на конфликты из модели совместимости
  - Предупреждения о слабых синергиях

ШАГ 7: Генерация концепции
  - Заполнение листа-геймификатора
  - AI-описание: как выбранные механики взаимодействуют
  - Определение core loop на основе выбранных механик
```

## 7. Рекомендации для внедрения в Gidede

### 7.1. Приоритетные модули

1. **Модуль «MechanicsDB»**: База данных 127 механик с атрибутами (группа, теги, совместимости, жанры). Основа для всех генеративных модулей. Каждая механика должна быть расширена: (а) формальными условиями применимости, (б) параметрами настройки (например, «Враги» → типы AI, количество, спавн-логика), (в) примерами из реальных игр, (г) связями с другими механиками.

2. **Модуль «Game Concept Generator»**: Алгоритмическая реализация 5 вариантов использования колоды. Вход: параметры → выбор механик из MechanicsDB → генерация концепции. Алгоритм на основе раздела 5.5.

3. **Модуль «Compatibility Checker»**: Валидация набора механик на конфликты и слабые синергии. На основе модели совместимости из раздела 5.3. Выход: предупреждения и рекомендации по замене.

4. **Модуль «Gameificator Sheet»**: Цифровая реализация листа-геймификатора. Заполняется AI на основе выбранных механик: название, жанр, платформа, мир, вид, core loop, целевая аудитория.

### 7.2. Интеграция с предыдущими книгами

- **127 механик (Колода)** + **16 паттернов (Адамс/Дорманс)** = каждая механика может быть проанализирована через паттерны: какая механика создаёт какую петлю обратной связи
- **127 механик (Колода)** + **113 линз (Шелл)** = для каждой механики — соответствующие линзы для проверки качества реализации
- **127 механик (Колода)** + **MDA Framework** = классификация: какие механики создают какие динамики и эстетики
- **4 стиля игры (LD, Кн. 14)** + **Группа 4 «Враги и бой»** = механики врагов адаптируются под Rusher/Sniper/Ninja/Opportunist
- **5 структур MP-карт (LD, Кн. 14)** + **Группа 7 «Социальность»** = мультиплеерные механики привязаны к макетам карт
- **Типология Engines/Economies/Ecologies (Селлерс, Кн. 13)** + **Группа 3 «Экономика»** = экономические механики классифицированы по типу системы
- **Матрица темпа 3×3 (LD, Кн. 14)** + **Группа 5 «Время»** = временные механики управляют темпом уровня

## 8. Контрольный список для AI-генерации на основе Колоды

- [ ] **Выбор базовых механик**: Минимум 3 из Группы 1?
- [ ] **Обязательная механика**: Есть хотя бы одна из {Враги, Головоломки, Изучение мира}?
- [ ] **Жанровое соответствие**: Выбранные механики соответствуют целевому жанру?
- [ ] **Совместимость**: Нет конфликтов между выбранными механиками?
- [ ] **Синергии**: Есть ли сильные синергии между выбранными механиками?
- [ ] **Прогрессия**: Определена система прогрессии (XP/технологии/перки)?
- [ ] **Боевая система**: Если есть «Враги» → определены боевые механики?
- [ ] **Пространство**: Определены пространственные механики (открытый/линейный)?
- [ ] **Core loop**: Можно сформулировать основной цикл на основе выбранных механик?
- [ ] **Геймификатор**: Все поля листа заполнены (название, жанр, платформа, мир, вид)?
- [ ] **Уникальность**: Комбинация механик создаёт уникальный опыт, а не клон?
- [ ] **Ограничения**: Есть ли перевёрнутые карты (запрещённые механики)?
