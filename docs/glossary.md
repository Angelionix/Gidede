## 1. Эстетики ЛеБланка (LeBlanc Aesthetics)

8 эстетических ценностей по Marc LeBlanc (MDA Framework). Определяют, **почему** игра приносит удовольствие.

| EN Term | RU Term | Определение (RU) |
|---------|---------|-------------------|
| Sensation | Чувственное удовольствие | Удовольствие от сенсорных ощущений — графики, звука, тактильной обратной связи. Игра как ощущения. Пример: ритм-игры, VR-опыты. |
| Fantasy | Фантазия | Погружение в вымышленный мир, роль иного персонажа. Игра как притворство. Пример: RPG, симуляторы жизни. |
| Narrative | Нарратив | Удовольствие от развития сюжета и драматургии. Игра как история. Пример: приключенческие игры, визуальные новеллы. |
| Challenge | Вызов | Преодоление трудностей, мастерство, рост навыков. Игра как испытание. Пример: Souls-like, головоломки, киберспорт. |
| Fellowship | Товарищество | Социальное взаимодействие, кооперация, соревнование с другими. Игра как социальная деятельность. Пример: MMO, партийные игры. |
| Discovery | Открытие | Исследование неизвестного, поиск тайн и новых территорий. Игра как исследование. Пример: Metroidvania, open-world. |
| Expression | Выражение | Самовыражение, творчество, персонализация. Игра как самовыражение. Пример: Sandbox, конструкторы, The Sims. |
| Submission | Подчинение | Привычное рутинное удовольствие, «залипание». Игра как времяпровождение. Пример: казуальные match-3, idle-игры. |

## 2. MDA Framework

Термины MDA-фреймворка (Hunicke, LeBlanc, Zubek, 2004). Определяет **три уровня** взаимодействия игрока с игрой.

| EN Term | RU Term | Определение (RU) |
|---------|---------|-------------------|
| Mechanics | Механики | Базовые правила, данные и алгоритмы игры. Уровень разработчика: параметры, ограничения, действия. Пример: «очки здоровья = 100», «урон меча = 25». |
| Dynamics | Динамики | Наблюдаемое поведение системы при взаимодействии механик во время игры. Уровень системы: как механики «оживают» в сессии. Пример: «игрок выбирает оборонительную тактику из-за высокого урона врагов». |
| Aesthetics | Эстетики | Эмоциональный отклик игрока при взаимодействии с динамиками. Уровень игрока: желаемые переживания. См. раздел 1. |
| MDA Pass | MDA-проход | Полный цикл анализа: от механик → динамики → эстетики (design) и от эстетики → динамики → механики (tuning). |
| Core Loop | Основная петля | Минимальный замкнутый цикл действий игрока, повторяющийся на протяжении всей игры. Основа геймплея. |
| Feedback Loop | Петля обратной связи | Циклическая зависимость, где результат действия влияет на последующие действия. Бывает positive (усиливающая) и negative (балансирующая). |
| Convergence | Сходимость | Степень, с которой динамики приводят к целевым эстетикам. Высокая сходимость = механики надёжно создают желаемый опыт. |
| Emergence | Эмерджентность | Непредсказуемое поведение, возникающее из взаимодействия простых механик. Желательное свойство для глубины геймплея. |
| Aesthetic Profile | Эстетический профиль | Распределение весов по 8 эстетикам ЛеБланка для конкретной игры. Определяет приоритеты дизайна. |
| Dynamics Profile | Динамический профиль | Набор динамик, выделенных из наблюдаемого геймплея. Связующее звено между механиками и эстетиками. |

## 3. Паттерны Адамса/Дорманса (Adams/Dormans Patterns)

Паттерны игровых механик из книги *Game Mechanics: Advanced Game Design* (Adams, Dormans, 2012). Формализуют структуры ресурсов и взаимодействий.

| EN Term | RU Term | Определение (RU) |
|---------|---------|-------------------|
| Static Engine | Статический двигатель | Источник, производящий ресурсы с постоянной скоростью. Не зависит от действий игрока. Пример: +10 золота каждые 30 секунд. |
| Dynamic Engine | Динамический двигатель | Источник, производящий ресурсы с переменной скоростью, зависящей от инвестиций игрока. Усиливающая петля. Пример: ферма, которую можно апгрейдить. |
| Converter | Конвертер | Механизм преобразования одного ресурса в другой по фиксированному коэффициенту. Пример: обмен золота на дерево (5:1). |
| Engine Building | Построение двигателя | Метра-механика: игрок строит или улучшает экономический двигатель. Усиливающая петля второго порядка. Пример: технологии в стратегиях. |
| Static Friction | Статическое трение | Постоянный расход ресурсов, не зависящий от действий игрока. Балансирующий механизм. Пример: подержание армии — 5 золота/ход. |
| Dynamic Friction | Динамическое трение | Расход ресурсов, зависящий от текущего состояния. Балансирующая петля. Пример: налог пропорционален доходу. |
| Stopping Mechanism | Останавливающий механизм | Механизм, ограничивающий рост: жёсткий потолок ресурса или активности. Пример: максимальный уровень 50. |
| Attrition | Истощение | Взаимный расход ресурсов двумя сторонами. Ресурс-война. Пример: урон по HP обоих бойцов. |
| Trade | Обмен | Обмен ресурсами между игроками или системами. Пример: торговля на рынке. |
| Multiple Feedback | Множественная обратная связь | Одна механика влияет на несколько петель одновременно. Создаёт сложную динамику. |
| Arms Race | Гонка вооружений | Усиливающая петля: обе стороны инвестируют в рост, не получая преимущества. Пример: эскалация мощи в RTS. |
| Escalation | Эскалация | Усиление сложности/награды пропорционально прогрессу. Пример: волны врагов становятся сильнее. |
| Playing Style Reinforcement | Усиление стиля игры | Выбор игрока в начале усиливается петлёй, делая альтернативы менее выгодными. Риск: потеря гибкости. |
| Milking | Выдаивание | Извлечение ресурса из источника, который не восстанавливается. Ограниченный ресурс. Пример: добыча руды из жилы. |
| Attrition/Escalation Combo | Комбо истощения и эскалации | Комбинация двух паттернов: усиление + взаимный расход. Типично для боёв в RPG. |

## 4. Линзы Шелла (Shell's Lenses)

Ключевые термины из книги *The Art of Game Design* (Jesse Schell). 113 линз для анализа игр.

| EN Term | RU Term | Определение (RU) |
|---------|---------|-------------------|
| Lens | Линза | Структурированный вопрос/набор вопросов для анализа определённого аспекта игры. Инструмент рефлексии дизайнера. |
| Tetrad | Тетрада | Четыре элемента игры по Шеллу: Механики (Mechanics), История (Story), Эстетика (Aesthetics), Технология (Technology). Все четыре должны работать согласованно. |
| Unity | Единство | Согласованность всех элементов игры: каждый элемент поддерживает общий опыт. Антипод — разрозненность. |
| Resonance | Резонанс | Сильный эмоциональный отклик, возникающий при единстве элементов. Когда игра «звучит» как целое. |
| Triangle of Weirdness | Треугольник странности | Фреймворк Скотта Роджерса: оценивает концепцию по трём осям — Персонажи (Characters), Мир (World), Активности (Activities). Если 0–1 ось «странные» — продаваемо, 2 — нишево, 3 — рискованно. |
| Experience | Опыт | Центральная категория Шелла: игра — это опыт. Дизайнер создаёт опыт, а не правила или графику. |
| Interest Curve | Кривая интереса | График вовлечённости игрока во времени. Идеальная кривая: нарастание → пик → спад → финальный кульминационный пик. |
| Iteration | Итерация | Цикл «создай → протестируй → оцени → улучши». Основной метод геймдизайна по Шеллу. |
| Prototype | Прототип | Быстрая реализация идеи для тестирования. Может быть бумажной, цифровой, физической. Главное — проверить гипотезу. |
| Playtest | Плейтест | Тестирование игры реальными игроками. Единственный надёжный способ узнать, работает ли дизайн. |
| 8 Filters | 8 фильтров идеи | Критерии оценки концепции: f1_experience, f2_audience, f3_motivation, f4_uniqueness, f5_feasibility, f6_scope, f7_fun, f8_prototype. |
| 30 Seconds of Fun | 30 секунд веселья | Тест: замкнут ли Core Loop за 30 секунд? Если цикл не приносит удовольствия за короткое время — он не работает. |
| Lens #1: The Lens of Essential Experience | Линза существенного опыта | «Какой опыт я хочу, чтобы игрок получил?» — отправная точка дизайна. |
| Lens #9: The Lens of the Elemental Tetrad | Линза элементной тетрады | «Согласованы ли все четыре элемента (механики, история, эстетика, технология)?» |
| Lens #16: The Lens of the Player | Линза игрока | «Что игрок делает физически, умственно, эмоционально?» |
| Lens #25: The Lens of the Model | Линза модели | «Какова математическая модель моей игры?» |
| Lens #31: The Lens of Challenge | Линза вызова | «Достаточно ли вызов? Слишком ли он труден? Присутствует ли поток?» |
| Lens #44: The Lens of Competition | Линза соревнования | «Соревнование нравится игрокам? Можно ли его улучшить?» |
| Lens #68: The Lens of Balance | Линза баланса | «Где игра недостаточно сбалансирована? Где она слишком сбалансирована?» |
| Lens #99: The Lens of Community | Линза сообщества | «Формирует ли игра сообщество? Что его удерживает?» |

## 5. Матрица Бонда (Bond Matrix)

Термины из книги *Unity и C#* (Джозеф Бонд) и собственного фреймворка Gidede для лудонарративного анализа.

| EN Term | RU Term | Определение (RU) |
|---------|---------|-------------------|
| Bond Matrix | Матрица Бонда | Фреймворк анализа игры как системы из 4 элементов × 3 уровня. Элементы: Механики, Нарратив, Эстетика, Технология. Уровни: Фиксированный, Динамический, Культурный. |
| Fixed Level | Фиксированный уровень | Постоянные, неизменные элементы, заданные разработчиком. Правила, сюжет, визуальный стиль, платформа. |
| Dynamic Level | Динамический уровень | Элементы, возникающие во время игры через взаимодействие. Геймплей-ситуации, эмерджентные истории, эстетика сессии. |
| Cultural Level | Культурный уровень | Элементы, возникающие в сообществе вокруг игры. Мемы, сленг, турниров культура, фанатское творчество. |
| Ludonarrative Dissonance | Лудонарративный диссонанс | Противоречие между нарративом (историей) и ludic (игровыми механиками). Когда история говорит одно, а геймплей — другое. Пример: «Натан Дрейк — хороший парень» (сюжет), но убивает сотни людей (геймплей). |
| Ludonarrative Harmony | Лудонарративная гармония | Согласованность между историей и механиками. Когда игровой опыт подтверждает нарратив. |
| Mechanic-Narrative Alignment | Выравнивание механик и нарратива | Степень, с которой механики поддерживают историю и наоборот. Цель дизайна — максимальное выравнивание. |
| Bond Element | Элемент Бонда | Один из 4 элементов матрицы (Mechanics, Narrative, Aesthetics, Technology), анализируемый на всех 3 уровнях. |
| Bond Cell | Ячейка Бонда | Пересечение элемента и уровня (4×3 = 12 ячеек). Каждая ячейка описывает конкретный аспект игры. |
| Ludonarrative Check | Лудонарративная проверка | Формализованная проверка согласованности между механиками и нарративом. Часть алгоритма 3.3 (Этап 6). |

## 6. Баланс игр (Game Balance)

Термины из книги *Игровой баланс. Наука* (Schreiber, Rogers) и общая теория баланса.

| EN Term | RU Term | Определение (RU) |
|---------|---------|-------------------|
| Transitive Balance | Транзитивный баланс | Баланс, основанный на числовом сравнении: если A > B и B > C, то A > C. Линейная шкала стоимости. Пример: оружие за 100 золота сильнее оружия за 50. |
| Intransitive Balance | Нетранзитивный баланс | Баланс по принципу «камень-ножницы-бумага»: A бьёт B, B бьёт C, C бьёт A. Нет однозначного лучшего выбора. |
| Q-Factor | Q-фактор | Отношение стратегической глубины к сложности освоения. Q = глубина / сложность. Высокий Q = легко научиться, трудно мастерить. |
| Dominant Strategy | Доминантная стратегия | Стратегия, всегда превосходящая альтернативы. Признак плохого баланса: игроки всегда выбирают один вариант. |
| Nash Equilibrium | Равновесие Нэша | Состояние, при котором ни один игрок не может улучшить результат, изменив стратегию в одностороннем порядке. |
| Cost Curve | Кривая стоимости | Зависимость эффективности объекта от его стоимости. Используется для транзитивного баланса. |
| Power Curve | Кривая силы | Зависимость силы/эффективности от прогресса. Должна быть монотонной, но не слишком крутой. |
| Diminishing Returns | Убывающая отдача | Каждый последующий вложенный ресурс приносит меньший прирост. Предотвращает бесконечный рост. |
| Symmetric Balance | Симметричный баланс | Одинаковые начальные условия и возможности для всех игроков. Типично для шахмат, RTS. |
| Asymmetric Balance | Асимметричный баланс | Разные возможности при равных шансах на победу. Сложнее в дизайне, но разнообразнее. Типично для class-based FPS. |
| Zero-Sum Game | Игра с нулевой суммой | Выигрыш одного игрока равен проигрышу другого. Пример: дуэль, шахматы. |
| Positive-Sum Game | Игра с положительной суммой | Возможен взаимовыгодный исход. Пример: торговля, кооперация. |
| Negative-Sum Game | Игра с отрицательной суммой | Общий результат меньше суммы вложений. Пример: гонка вооружений. |
| Penalty | Штраф | Механизм отрицательной обратной связи за определённое действие или состояние. Балансирующий фактор. |
| Bonus | Бонус | Механизм положительной обратной связи. Усиливающий фактор. |

## 7. Core Loop и петли

Термины, связанные с проектированием основной петли игры (алгоритм 3.2).

| EN Term | RU Term | Определение (RU) |
|---------|---------|-------------------|
| Core Loop | Основная петля | Минимальный замкнутый цикл действий, который игрок повторяет на протяжении всей игры. Основа геймплея. |
| Inner Loop | Внутренняя петля | Самый базовый цикл действий (микро-уровень). Обычно занимает секунды-минуты. Пример: выстрел → попадание → урон → смерть врага → лут. |
| Outer Loop | Внешняя петля | Цикл, охватывающий несколько итераций внутренней петли. Обеспечивает среднесрочную мотивацию. Пример: заработал золото → купил снаряжение → стал сильнее. |
| Meta Loop | Мета-петля | Самый верхний уровень: долгосрочные цели, удержание (retention). Сезоны, эндгейм, социальные цели. |
| Reinforcing Loop | Усиливающая петля | Положительная обратная связь: действие усиливает само себя. Риск: runaway-эффект (неограниченный рост). |
| Balancing Loop | Балансирующая петля | Отрицательная обратная связь: действие ослабляет само себя. Стабилизирует систему. |
| Loop Hierarchy | Иерархия петель | 6-уровневая структура: micro → task → session → quest → campaign → meta. Каждый уровень охватывает предыдущий. |
| Structural Type | Структурный тип | Классификация Core Loop: Engine (накопление), Economy (обмен), Ecology (баланс), Hybrid (комбинация). |
| Engine Type | Тип «Двигатель» | Core Loop, основанный на накоплении ресурсов. Усиливающая петля. Риск: runaway. Пример: idle-игры, кликеры. |
| Economy Type | Тип «Экономика» | Core Loop, основанный на обмене ресурсов. Балансирующая петля. Пример: торговые симуляторы, стратегии. |
| Ecology Type | Тип «Экология» | Core Loop, основанный на балансе производства и потребления. Пример: survival-игры, градостроительные симуляторы. |
| Pathology | Патология | Проблема в структуре Core Loop. 7 видов: Runaway, Deadlock, Stall, Brittleness, Oscillation, Stagnation, Triviality. |
| Runaway | Неограниченный рост | Патология: ресурс растёт бесконечно без ограничивающего механизма. |
| Deadlock | Тупик | Патология: замкнутый цикл зависимостей, ни одно действие не может начаться. |
| Stall | Остановка | Патология: петля перестаёт выполняться из-за нехватки ресурса. |
| Brittleness | Хрупкость | Патология: малое изменение одного параметра ломает всю систему. |
| Oscillation | Колебание | Патология: система колеблется между двумя состояниями без стабилизации. |
| Stagnation | Застой | Патология: петля выполняется, но не приносит прогресса. |
| Triviality | Тривиальность | Патология: решение всегда очевидно, нет интересного выбора. |

## 8. Общие термины геймдизайна

| EN Term | RU Term | Определение (RU) |
|---------|---------|-------------------|
| Game Design Document (GDD) | Документ игрового дизайна | Полное описание игры: концепция, механики, нарратив, арты, технические требования. Живой документ, обновляемый в ходе разработки. |
| One-Pager | Одностраничник | Краткое описание концепции на одной странице: story synopsis + gameplay description. Используется для быстрой оценки идеи. |
| USP (Unique Selling Proposition) | Уникальное торговое предложение | Главная отличительная черта игры, которую нельзя найти у конкурентов. Обоснование: зачем играть именно в эту игру. |
| MechanicsDB | База механик | Справочник из 128 игровых механик, сгруппированных в 15 категорий. Используется для подбора механик по жанру и эстетике. |
| Prompt Registry | Реестр промптов | Каталог из 34 AI-промптов, формализованных для Gidede. Каждый промпт: id, тип задачи, входы/выходы, модель, гарантии. |
| Concept | Концепция | Результат Блока 1: жанр, эстетики, механики, Core Loop, USP, One-Pager. Отправная точка для всех последующих блоков. |
| Genre | Жанр | Категория игры по таксономии Роджерса: Action, Adventure, RPG, Simulation, Strategy, Puzzle, Party, Educational, Racing, Sports. |
| Subgenre | Поджанр | Уточнение жанра: roguelike, souls-like, metroidvania, RTS, MOBA и т.д. |
| Player Motivation | Мотивация игрока | Внутренняя причина, по которой игрок играет. По Bartle: Achiever, Explorer, Socializer, Killer. По Quantic Foundry: Action, Social, Mastery, Achievement, Immersion, Creativity. |
| Retention | Удержание | Способность игры удерживать игрока во времени: D1, D7, D30. Зависит от качества мета-петли и контента. |
| Progression | Прогрессия | Система роста возможностей игрока во времени. Вертикальная (цифры растут) и горизонтальная (новые опции). |
| Economy | Экономика | Система производства, распределения и потребления ресурсов в игре. |
| Monetization | Монетизация | Способ получения дохода от игры: F2P + микротранзакции, премиум, подписка, DLC. |
| Playtesting | Плейтестирование | Тестирование игры реальными игроками для выявления проблем и сбора обратной связи. |
| Game Feel | Ощущение игры | Интуитивное восприятие качества взаимодействий: отзывчивость управления, вес объектов, juiciness эффектов. |
| Juiciness | Сочность | Избыточная визуальная/звуковая обратная связь, делающая действия приятными. Частицы, тряска экрана, звуковые эффекты. |
| Flow State | Состояние потока | Оптимальное состояние между скукой (слишком просто) и тревогой (слишком сложно). По Csikszentmihalyi. |
| Skill Chain | Цепочка навыков | Последовательность навыков, которые игрок осваивает по мере прогрессии. Каждый навык строится на предыдущем. |
| Onboarding | Обучение | Процесс знакомства нового игрока с механиками и правилами игры. Первые 5–15 минут. |
| Endgame | Эндгейм | Контент для опытных игроков, исчерпавших основной прогресс. Гораздо более сложный и социальный. |

## Правила использования

1. **Все документы проекта** используют термины из данного глоссария
2. **При неоднозначности** — предпочтение за английским термином с русским переводом в скобках при первом упоминании
3. **Обновление** — при добавлении новых терминов обновлять глоссарий и указывать источник
4. **Кросс-ссылки** — термины из разных секций связаны (например, Aesthetics в MDA и LeBlanc — одно и то же)
