## 1. Текущее состояние (As-Is)

Gidede — AI-powered система для геймдизайнеров, проводящая игру от идеи до GDD через **8 функциональных блоков**. Портирована с Python/FastAPI на чистый Next.js 16 API Routes.

### Технологический стек
| Слой | Технология |
|------|-----------|
| Frontend | Next.js 16 + TypeScript 5 + Tailwind CSS 4 + shadcn/ui |
| Backend | Next.js API Routes (TypeScript) |
| БД | SQLite (Prisma ORM, 14 таблиц) |
| AI | z-ai-web-dev-sdk (glm-4.6) |
| Прототипы | LittleJS (2D) + Three.js (3D) |
| Node-редактор | @xyflow/react (React Flow) |

### Что работает (подтверждено деплоем и Agent Browser)
- **8 блоков** реальные (не заглушки): Concept, Core Loop, MDA, Balance, Progression+Economy, GDD+Checklist, AI Assistant (SSE), GBE Bridge (mock-но-честный).
- **AI-интеграция**: `z-ai-web-dev-sdk` server-only, singleton с graceful fallback на детерминированную логику при недоступности SDK.
- **RAG по Библии**: 12 секций / 494 чанка / 10945 терминов (TF-IDF) — подтверждено эндпоинтом `/rag/stats`.
- **MechanicsDB**: 128 механик SW.BAND / 15 групп — подтверждено.
- **Node-based prototype editor** (Phase 1–3 ROADMAP): React Flow canvas, 20 типов нод, 5 шаблонов, валидатор, AI-генерация графа из текста/GDD, компиляция в LittleJS HTML.
- **Auth**: scrypt + HMAC-SHA256 JWT, httpOnly cookies, access 30 мин / refresh 30 дней.
- **64 API-эндпоинта** под `/api/v1/*` (README утверждает 59 — устарело).
- **Lint чистый**: 0 ошибок, 0 предупреждений; 0 `TODO/FIXME`, 0 `eval`, 0 `@ts-ignore`.
- **Dark mode** через next-themes, отзывчивая вёрстка, экспорт GDD в DOCX.

### Ключевые метрики кода
- Файлов в репо: ~279 (после очистки)
- Строк в `ai-service.ts`: 973
- Тестовое покрытие: **0%** (нет ни одного `*.test.ts`/`*.spec.ts`, нет тест-раннера)
- Веток: `nextjs-port` (активная), `main` (только доки), `python-original` (старый бэкенд)

### 🔴 Критичные (блокируют production-ready)

| # | Проблема | Файл:строка | Влияние |

| C1 | **Серверный пайплайн — заглушка** | `api/v1/pipeline/run-full-pipeline/[projectId]/route.ts:69-82` | `run-full-pipeline` и `run-pipeline` возвращают `"Mock-выполнение"` без сохранения данных. Реальная оркестрация — только клиентски в `pipeline/page.tsx`. |

| C6 | **`typescript.ignoreBuildErrors: true`** | `next.config.ts:7` | Прод-сборка пропускает проверку типов. В комбинации с 0% тестов типобезопасность не верифицируется. |
| C7 | **Dockerfile healthcheck сломан** | `Dockerfile:71` | `HEALTHCHECK` использует `curl`, но `node:20-slim` его не содержит → контейнер всегда `unhealthy`. |

### 🟡 Минорные / технический долг

- **JSON-blob антипаттерн**: 8–15 структурированных полей на блок хранятся как `String? // JSON` — неповоротливо, нетипизировано, неиндексируемо (`schema.prisma:107-113` и др.).
- **Отсутствуют индексы** на `Project.userId`, `ChatMessage.userId` (сингл), `PlaytestResult.userId`, `SavedMechanic.userId`, `PrototypeGraph.userId`, `GbeSyncHistory.userId` — full scan при фильтрах.
- **`Project.version`** существует, но нигде не инкрементируется.
- **Нет soft-delete / audit-полей** (`deletedAt`, `createdBy/updatedBy`).
- **Комментарий в схеме врёт**: `User.hashedPassword` помечен «bcrypt», реализация — scrypt.
- **Нет FK-отношений** между `PlaytestResult`/`SavedMechanic`/`PrototypeGraph` и `Project` (только raw `projectId String?`) — нет каскадного удаления.
- **`localStorage['gidede_active_project']`** читается через `typeof window !== 'undefined'` в 6+ местах — race-prone, не SSR-безопасно.
- **`PrototypeEditor`** — фиксированная высота `h-[calc(100vh-3.5rem)]` и `w-56` инспектор, не адаптируется на мобильных.
- **Блоки 7 и 8** дублируют fetch-логику вместо общего `apiFetch` из `auth.tsx`.
- **README устарел**: 59 эндпоинтов → реально 64; нет упоминания, что server-pipeline — mock.
- **`.env.example` отсутствует** — README ссылается на `cp .env.example .env`, но файла нет.

10. **Миграция БД**: `prisma migrate` не удаляет данные (в отличие от `db:push --accept-data-loss`).

## 10. Общая оценка

Gidede — **существенно готовый, действительно рабочий MVP**, не «каркас». 8 блоков реальные, AI-интеграция настоящая (с graceful fallback), RAG и MechanicsDB соответствуют заявкам, lint чистый, TODO-долга нет. Архитектурных блокеров нет.

Главные слабые места — **ограниченные и точечные**: mock-серверный пайплайн, наполовину готовый компилятор графа (12/20 нод инертны), нулевое автотест-покрытие и кластер production-readiness-проблем (JWT-секрет, Dockerfile healthcheck, `.env` в git, `ignoreBuildErrors`, XSS в GDD-превью).

Приоритет — **Фаза 1 (1–2 недели)** закрывает все критичные security/deploy-проблемы и делает пайплайн реальным. После этого проект можно считать безопасно-деплоябельным. Фазы 2–3 доводят функционал и качество до v1.0.
