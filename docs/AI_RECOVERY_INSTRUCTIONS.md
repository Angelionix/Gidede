## 1. Обзор проекта

### Что такое Gidede

**Gidede** — это AI-first система для геймдизайна, объединяющая формализованные методологии из 17 книг по геймдизайну с генеративными возможностями AI. Система выступает как интеллектуальный ассистент, который не заменяет геймдизайнера, а усиливает его: помогает генерировать концепции игр, проектировать Core Loop, балансировать механики, моделировать экономику и создавать GDD.

**Ключевой принцип**: «Алгоритмы — для вопросов „сколько" и „правильно ли", AI — для вопросов „что если" и „почему"».

### Текущая фаза

Проект завершил исследовательскую и документальную стадии (Фазы 1–3) и находится в активной разработке **Фазы 4: Разработка веб-приложения**. Текущий прогресс: субфазы **4.A** (инфраструктура), **4.B** (Блоки 1–3) и **4.C.1–4.C.4** (Блок 4) завершены. Следующие задачи: **4.C.5–4.C.9** (Блок 5 и сквозной пайплайн).

```bash
git pull
```

#### Шаг 2. Настройка remote для push-операций (PAT workflow)

Для отправки изменений в GitHub используется Personal Access Token (PAT). **ВАЖНО**: PAT хранится в remote URL только на время push-операции, после чего немедленно удаляется.

**Перед push** — установить PAT в remote URL:

```bash
git remote set-url origin https://<PAT>@github.com/Angelionix/Gidede.git
```

> 📋 **PAT хранится в файле `docs/SECRETS.md` (не в репозитории) или уточняется у владельца проекта.**

**После push** — немедленно убрать PAT из remote URL:

```bash
git remote set-url origin https://github.com/Angelionix/Gidede.git
```

> ⚠️ **КРИТИЧЕСКОЕ ПРАВИЛО**: Никогда не оставляйте PAT в remote URL после завершения push. Это угроза безопасности. PAT может быть скомпрометирован, если останется в конфигурации Git.

#### Шаг 3. Проверка состояния репозитория

```bash
cd /home/z/my-project/Gidede/
git status
git log --oneline -10
```

Убедитесь, что рабочая директория чистая (`nothing to commit`) и вы на ветке `main`.

## 5. Git workflow

### Базовый рабочий процесс

```
1. Перед началом работы:
   cd /home/z/my-project/Gidede/
   git pull

2. После внесения изменений:
   git add .
   git commit -m "тип: краткое описание на русском"

3. Отправка в GitHub (PAT workflow):
   git remote set-url origin https://<PAT>@github.com/Angelionix/Gidede.git
   git push
   git remote set-url origin https://github.com/Angelionix/Gidede.git
```

### Правила коммитов

- **Всегда** перед работой: `git pull`
- **Сообщение коммита** — краткое описание на русском языке
- **Префиксы типов коммитов**:
  - `док:` — добавление/обновление документации
  - `фаза1:` — изменения в анализе книг
  - `фаза2:` — изменения в Библии геймдизайна
  - `фаза3:` — изменения в алгоритмах
  - `фаза4:` — изменения в коде веб-приложения
  - `фикс:` — исправления
  - `рефактор:` — рефакторинг

### PAT workflow — подробная инструкция

```bash
# 1. Убедитесь, что вы в правильной директории
cd /home/z/my-project/Gidede/

# 2. Добавьте PAT в remote URL
git remote set-url origin https://<PAT>@github.com/Angelionix/Gidede.git

# 3. Выполните push
git push

# 4. НЕМЕДЛЕННО уберите PAT из remote URL
git remote set-url origin https://github.com/Angelionix/Gidede.git

# 5. Проверьте, что PAT удалён
git remote -v
# Должно быть: origin  https://github.com/Angelionix/Gidede.git (fetch)
#              origin  https://github.com/Angelionix/Gidede.git (push)
```

> ⚠️ **Никогда не пропускайте шаг 4.** PAT в конфигурации Git — это утечка учетных данных.

### Принципы проектирования

1. **Reverse MDA как центральный принцип** — от желаемого опыта (эстетика) к конкретным правилам (механики)
2. **Чёткое разделение AI и алгоритмов** — AI для генерации и интерпретации, алгоритмы для расчётов и валидации
3. **Контекстная осведомлённость** — каждый модуль знает состояние проекта (Единая модель проекта / Project State)
4. **Фреймворк-осведомлённость** — система ссылается на конкретные концепции из 17 книг
5. **Модульность** — каждый функциональный блок самостоятелен, но обменивается данными через Project State
